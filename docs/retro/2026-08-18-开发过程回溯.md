## 二、起点：这不是从零开始的

**做之前，v0 已经跑了几个月，而且是纯人肉的。**

- Claude 的定时任务（scheduled task）当 scout，每周替他找机会
- 每个机会进来，他手动判断跟哪个项目有关、要不要改作品、怎么申请
- 然后**手动开一个新的 Claude chat**，把这个机会接着聊、养大

这一段很关键，讲给别人听的时候先讲这个：

> **最大的风险（「AI 能不能当外联 producer」）已经被用行动验证过了。缺的从来不是智能，是骨架。**

v0 的三个糙点，正好是产品要补的三样：

1. 机会散在一堆**互相失忆的 chat** 里，每条都得重新喂背景
2. 没有一个地方能一眼看到「我手上在推哪些机会、各自到哪一步」
3. 每条线的上下文全靠人在脑子和聊天记录之间**手动搬运**

于是第一份设计稿（08-01）把定位写成一句话：

> **一个艺术家请不起的 producer / BD —— 用一个不失忆的 agent 补上。**

以及四根柱子：① 不失忆 ② 有流程 ③ 懂你的作品网 ④ 一起想。

第四根是定盘星，它决定了界面长什么样：

> 这不是一个自动化流水线（你按钮、它吐草稿），是一个**共同思考的台面**。最后那份申请是你俩讨论出来的残留物。

## 三、时间线：六个阶段

### 阶段一 · 骨架（08-01 → 08-04）

三份设计稿先落地，然后代码才进版本控制。

- 08-01 总设计稿：机会线是基本单位、四根柱子、里程碑
- 08-03 **brain sidecar**：想清楚「那个对话框到底接什么」。三档路线摆开——裸 API / Claude Agent SDK / 继续在终端里聊——选了 Agent SDK，因为它能挂订阅、能力最全，自用阶段一分钱不花
- 08-03 作品库升级成「主人信息库」：作品 + 履历 + 战绩 + 自述，57 条，都是 agent 的弹药
- 08-04 首次提交，同一天九列并七列、页面分成三个主区、改名「渡 → Fairwind」

**这一阶段最值得讲的判断**：记忆的唯一真相源必须是数据库，**不许住在 Claude Code 的 session 文件里**。因为那正是 v0 散架的病根——一个 session 一个文件、按工作目录分组、`/clear` 就断片、应用查不到。

### 阶段二 · 从账本变成操作台（08-05 → 08-06）

08-05 那份设计稿开头有一节，标题是「先说清楚现在是怎样」：

> **今天真正干活的不是 Fairwind，是终端里的 Claude Code。**
> 库里那 20 封邮件、那份 88 词的草稿——一行都不是页面产生的。
> **页面到今天为止是一个账本，不是一个操作台。**

这一刀之后：三栏（卷宗 / 商量 / 交付）、产出模型（草稿→定稿）、邮件真正接进来。
08-06 补上「更新最新信息 + 批量操作 + 过卡队列」——因为发现每一个动作都是单张的，26 张新卡逼着你一张张来。

### 阶段三 · 人（08-08 → 08-09）

导火索是一封信：

> 邮箱里躺着一封信。发信的人是别人介绍来的。**你打不开这封信，因为一打开就得写。**
> 上下文你都记得，该不该回你也判断得了——卡住的只有一件事：**下不去笔**。
> 而系统帮不上忙，因为他不是一条机会线。库里所有起草的机器第一列都是 `pursuit_id not null`。他一步都上不去。

这一刀做了个结构手术：三张表的 `pursuit_id` 改成可空 + 新增 `contact_id` + `check (二者至少有一个)`。做完之后，验收表里**七步有六步是现成的**。

顺带推翻了 08-04 自己写下的判断（「人际管理装的是没有 proposal 压力的朋友」）：

> **这句是错的。人是一个独立的层。项目争取和人际管理是看这一层的两个入口，共用同一张名片。区别在谁在推你。**

还有一段是真的去查了美国 networking 的规矩，然后**规矩直接改了引擎的形状**：

- 「just checking in」在美国是公认最没用的邮件 → 所以引擎不该产出「该问候了」，**它该产出「该给他看点什么了」**
- 「circle back next semester」是真话不是客套，婉拒长的是另一个样子（不给时间锚点）→ 判据变成：**给了时间锚点的是真的**
- warm intro 有个闭环（回头谢介绍人）大多数人不做 → 变成一条由头

### 阶段四 · 换水管（08-10 → 08-12）

**这是整个项目最大的一次翻案。**

事故：手动发出去的六封信、三封回复，按「更新最新信息」一封都收不到。查下去发现是个死结——

> 反查 thread 需要库里先有信，而信要进库先得有 thread。你在 Gmail 里手动发的信两条都不占。

数字比故事清楚：**65 条机会线，只有 3 条登记过 thread。「还不认识的地址」= 0 —— 那个 0 不是干净，是从来没有信进来过。**

于是拆了 claude.ai 的 Gmail 连接器，brain 自己拿 OAuth 直连 Gmail API。核心判断是：

> **抓取和理解要分开。** 连接器的工具只有模型能调，于是每取一批信都要花一次模型往返。换掉之后，抓取是纯 HTTP，模型只在「这个地址背后是谁」那一步出场。

以及三层漏斗（判断的单位是**地址**不是邮件，地址比邮件少两个数量级）：

1. 信头就能判掉（`List-Unsubscribe`、`no-reply@`、`Precedence: bulk`）—— 纯 SQL，零成本
2. 最强的正面信号：**你有没有主动发过信给他** —— 纯 SQL
3. 剩下的残渣才交给模型 —— 一张 150 token 的地址卡，五十张一批。**这一层最不能漏，因为漏掉的都是曾经找过你而你错过的人**

成本算过：1500 个地址一次性判完，最贵的档约 $2.3。

### 阶段五 · 打磨与分家（08-13 → 08-15）

- 骨架与血肉分家：`demo/` · `src/demo/` · `supabase/demo/` 三处装内容，其余都是骨架
- 对话边想边出字（SSE 流式）
- 「重说」：说错一句能撤掉它和它之后的对话，重来
- prompt 切三档：把 21,898 字符的静态块搬进 `systemPrompt`，让缓存真能命中

### 阶段六 · 闭环（08-16 → 08-18）

- **直接发信**：信封 `[[LETTER]]` → 收进产出 → 在产出里改 → 两段确认 → 真发出去 → 当场记账
- 申请表也走同一条路（`[[FORM]]`，一格一个字数闸）
- 08-18 顶栏通知：把机会线和人两边的判据**合成一套**，三层（手头 / 老账 / 判为不用回的）

## 四、故事库（社媒素材，每条都能单独发）

### 1. 「宁可不说，也不猜」——第一次删功能，待处理从 28 张掉到 1 张

球权（球在谁那边）原来有个兜底：没有往来记录时，按卡在哪一列猜。

> **那是个错误。**「走到哪一格」和「现在该谁动」是两件事，用前者猜后者，猜出来的是一个**看着很确定、其实没有依据**的答案。

撤掉之后只剩两个真实信号：跟进日到期、最后一封真实通信是谁发的。都没有 → 什么都不显示。

**代价看得见：待处理从 28 张掉到 1 张。那消失的 27 张本来就没有依据。**

这句「宁可不说，也不猜」后来被引用了至少五次，成了整个项目的第一判据。

---

### 2. 一个字段装了四种意思，于是卡上经常说错话

`next_touch_at` 一个字段被拿来装四种意思，结果：

- 「8 天后跟进」其实是人家 8 天后**才开放**
- 3 天后截止的那条**什么都不显示**
- 说该跟进的那条，你早回过邮件了

拆成六个字段（`opens_at` / `deadline` / `deadline_at` / `next_touch_at` / `next_action` / `last_touch_at`），每个一种意思。顺带定了「勾掉 ≠ 删掉」：原文留着，只写 `done_at`，取消勾还能回来。

---

### 3. 「看不见 = 丢了」——这条铁律是踩出来的

改七个列名的时候，先改了前端、后补数据库的兼容层。中间那段时间里，看板一列都筛不到。

> **用户看到的是「卡片弄丢了」。对一个天天在用的系统，看不见 = 丢了。**
> 以后改数据形状，兼容层和改动必须**同时**落地。

这条后来长成了整个项目的第一铁律，并且不断被引用：

- 「你为什么在队里」那段**渲染了，但被自动滚动推到可视区外 680px** —— 东西在，你永远看不见。同一类病，第三次不许再踩
- AI 判掉 2,847 个地址，**一个都不删**，给一个搜索框：「搜一下，看看有没有冤枉的」。那一页从**待办清单**变成**档案柜**
- 查了但没建卡的**负面结果**也写进战报
- 位置也是信息 —— URL 记着你在哪，刷新不弹回首页

### 4. 红点在撒谎，而且它撒的谎正好盖住了唯一值得响的那件事

九张卡挂着红点，人明明点开看过了，收起来又亮。查下去是三个缺陷叠在一起：

1. 没记录就当 1970 年 —— 「从没点开过」和「有新消息」变成同一件事
2. 建卡时自带的那份 brief 也算「Fairwind 说话」→ 一批新卡**从出生起全亮**
3. 已读只活在一个浏览器的 localStorage 里 —— 两个窗口开同一个地址，一个显示 `1/2` 一个显示 `1/1`

**而它盖住的那件事**：判据只认 `role='producer'`。**对方机构真回信了——不亮点。**

> 红点最该响的那一下，恰恰是它唯一不响的那一下。

改完之后有一句验收结论很好用：

> 全盘 65 张卡现在 0 未读。**这是实话——你确实全读过了，原来那些红点全是假的。**

### 5. 「假装在想」：三个点转了一整天，而根本没有东西在跑

`busy` 的判据原来是「最后一条是你发的」。这是猜的。

库里躺着一条实证：某条线上 05:33 问的那句后面**没有任何回复**，那次没想完。于是那条线**永远显示三个点**，而且输入框被 `disabled={busy}` 永久禁用——你连再说一遍都做不到，整条线就此锁死。

改成：只有「刚发出、还在 3 分钟窗口内」才算在想；超了就承认它没回，把输入框还给你，并明说「再说一次就行」。

---

### 6. 点点串台：React 复用了同一个组件实例

「我没说新的话，它却在转点点」。

抽屉是一张接一张换的，但组件没有 `key`，React 复用同一个实例只换 props——你在 A 卡问完立刻点开 B 卡，**B 卡凭空转起点点；A 的回复回来时还会把消息塞进你正看着的 B 卡**。

加一行 `key={pursuit.id}` 就好了。但这条的价值在后半段：

同一次排查里发现，**跑着的 brain 进程是前一天启的**，早于「讲懂改成后台扫」那一刀。于是前端触发器删了、后台扫描从没跑起来，**整整一天没有一张新卡被读过，谁也没发现**。

> 跟「迁移写了没跑」是同一个病：东西写了，没让它真正生效。

修法：`/health` 带一个 build 日期，前端存同一个值，对不上就在顶栏说「脑子跑的是旧代码，重启一下」。

### 7. 「静默失败是最坏的情况」

这条被写进设计稿三次。因为它犯过：

- 「讲懂」改后台之后一天没读过卡，没人发现
- `handleSync` 其实返回了一句实话（「这条线还没有任何邮件往来」），而调用方**把那句话整个丢掉了** —— 进度条走完，屏幕上一点动静没有
- Google OAuth 同意屏幕停在 Testing，refresh token **7 天过期**。挂掉的样子是「这轮 0 封新信」，**跟真的没有新信长得一模一样**

规矩：每一轮都要报「跑了什么、拿到几封、判了几个」，**包括 0**。「没有新信」这句话也必须出现在屏幕上。

---

### 8. 她的信不是丢了，是从来没进来过

某位联系人卡上写着「上次碰 7/2」，而她 8/10 刚回过信。

库里认领了 4 条 thread，Gmail 里她三个地址下有 20 条。漏掉的里面有一条是**正在进行的对话**，还有整整三个月的往来。

病根是自己立的一条原则：「只拉登记过的 thread，永远不遍历信箱」。

> 那条对**机会线**是对的（一条线就那么几串往来），对**人**是错的（你要的是这个人的全部往来）。
> 而且错得很难发现——**信没丢，只是从来没进来过，于是那个日期在撒谎，比空着更坏。**

改完真跑：20 条 thread、52 封新信，归属零错。「上次碰」从 7/2 变成 8/10，往来从 7 封变成 59 封，最早追到 2025-04-30。顺带认出一个时间锚点：9 月 5 号她有个闭幕派对，邀你去。

### 9. 差一天：你 8/13 傍晚记的一笔，写着 8/14

```
存的（UTC）      2026-08-14 00:11:49
洛杉矶当地       2026-08-13 17:11:49   ← 你按下按钮的那一刻
库里算的日期     2026-08-14            ← 页面显示的
当地的日期       2026-08-13            ← 你经历的
```

> 差一天这种事最阴：不报错、不崩、看着完全正常，只是**每天傍晚之后记的东西全部记到明天去**。等你哪天照着这些日期回想「我什么时候跟他聊的」，拿到的是一份**系统性偏移的记忆**。

还有一个细节值得单独说：**不按浏览器时区，按你档案里填的常住地。**

> 你出差纽约那三天，不该让所有历史日期集体跳一格——「那封信几号来的」是事实，不该跟着行程变。

以及一段自己认错：上一版特意把某个函数改成 UTC，理由是「对齐库里的值」。

> 对齐是对了，但**对齐到了错的那一边**。

### 10. 共享信箱不是垃圾

三层漏斗跑完第一批 50 个真地址，人工抽查抓出两个错：

一个艺术节主办方的共享信箱——跟他 80 封往来、给他出过 O-1 支持信——被规范化函数折成 `machine`，**静默丢掉**。

> 共享信箱不是人（硬当人会归错到某个倒霉蛋头上），**但它跟业务的相关性一点不比人低。**

于是 `shared_box` 变成独立一档，走「登记成机构信箱」那条路。221 个判定作废重判。

**这条的教学价值**：AI 判完之后人工抽查 50 个，抓出两类系统性错误——这是「用 AI 做判断」的正确姿势，不是信它，也不是不用它。

### 11. 同一个人建了两张卡，而模型自己看出来了

一天撞了三次：一个笔误域名、一个名字三种写法、一个私人 Gmail。

> 模型每次都自己看出来了——备注里明明写着「疑似笔误」「应该是同一个人的另一个地址」——**但还是各建了一张卡。**
> 因为 prompt 只问「这是谁」，没问「这是不是通讯录里已有的谁」。

老路子（粘个邮箱查）本来就有这个判断，批量那条路漏了那一步。

**这条特别适合讲给学 AI coding 的人听：模型的输出里已经有答案了，是你没问那个问题。**

### 12. 20 轮的自言自语，被当成回复存了下来

`think()` 原来把一次「想」里每一轮的文字块无差别攒起来。可 `maxTurns` 是 20 配着联网工具，中间那些轮次产出的不是回答，是**工作稿**——"I'll start by loading the web tools."、"Let me fetch it."、整段整段的英文中间报告。

> 最长的一条 31,925 字符，其中 **27,698 是工作稿**。它们既摆在她眼前，又每轮都被重新塞进 prompt。

判据很干净：

> **动工具之前说的话都是工作稿。** 它要去查资料，说明还没想完；想完了才不用再动工具。

工作稿不销毁，进 `meta.notes`——里面是真查到的 URL 和核实记录。已经落库的那 8 条，**给每条一个锚点、让 Postgres 在库里那份原文上自己切**，不是拿副本去覆盖；锚点都验证过只出现一次；原文整条进 `meta.raw`，一句 SQL 能还原。

### 13. 修好的那一条，引进了一个新的卡死

上一条修复把 `resolve` 挪进 `server.close(cb)`，为的是「等服务真关完再交差」。

> 但 `close` 的回调要等**所有连接断开**才触发，而浏览器保着 keep-alive 不放——于是真跑的时候：code 收到了、端口不监听了、**进程却永远卡着**。用户那边看到的是「点完同意就没反应」。
> 上一条测试用 `fetch`，连接关得快，正好漏掉这个形态。

补的回归测试用 `http.Agent` keepAlive，判据是**必须在 5 秒内 resolve**，不是「最终会 resolve」。

### 14. 仓库里没有的那六支迁移

`pa_add_mail` / `pa_claim_email` / `v_pa_unknown_senders` 这些归属层的核心对象**只活在线上库里**，`migrations/` 目录停在 0037。

> 没有这几条，谁都重建不出这个库。

修法讲究：由 `supabase_migrations.schema_migrations.statements` **逐字 dump**，不是事后凭记忆重写定义。

同一类病还有一次：四个模块文件被 import 了，但**落在工作区没提交**。

> 后果是从干净 checkout 起不来：前端 import 空，脑子一跑就崩。本地开发看不出来，因为文件在磁盘上——**跟「迁移写了没跑」是同一个病。**

### 15. 拆家：什么是骨架，什么是血肉

要让别人 fork 这个仓库，就得把「系统」和「一个人的内容」拆开。这一刀最容易分错的地方：

> **「形状」不是血肉。**
> 「为什么有起草这一层」——因为他怕发冷邮件；「为什么有 scout」——因为他信息收集能力弱。
> 这些卡点决定的**功能形状必须留下**，因为剥掉它们剩下的是一个**通用机会管理器**，那个东西帮不了任何人。
> 别人 fork 下来要改的起点，得是**一个有观点的东西**，不是一张白纸。

顺带拆了四颗雷：种子文件里有四处 `truncate` / `delete`，其中一条会顺着外键把 65 条机会线连同全部往来历史一起铲。

修法不是删掉 truncate（删了重跑会重复插入），而是**每支种子自己检查**：发现库里 `is_demo = false` 就整支中止，一行都不删。而且这一列**默认 false**——

> 现有的库自动受保护，什么都不用做。**不是靠我小心，是结构上碰不到。**

## 五、沉淀下来的判据（这部分最值得教）

这十几条不是从书上抄的，每一条背后都有一次具体的疼。教朋友的时候，这是「web coding 自己做工具」真正的门槛所在——**写代码 AI 帮你，定判据得你自己来。**

| 判据 | 从哪次疼里长出来的 |
|---|---|
| **宁可不说，也不猜** | 球权从 stage 猜，猜出 27 张假的待处理 |
| **看不见 = 丢了** | 改列名时前端先行，用户看到「卡片弄丢了」 |
| **一个字段一种意思** | `next_touch_at` 装了四种意思，卡上经常说错话 |
| **空着可以，假着不行** | 四个死 tab 占了两天位；人际管理是空页但不是白页 |
| **能算出来的就算，算不出来的才存** | 存下来的会跟事实分叉，算出来的不会 |
| **系统只报事实，判断归你** | 系统会悄悄改回你手动点的标签，而你收不到通知 |
| **静默失败是最坏的情况** | 犯过三次，每次都是「看着一切正常」 |
| **先落原文，后写摘要，顺序不能反** | 反过来做，脑子一挂那封信就永远不存在了 |
| **护栏是结构，不是嘱咐** | 见下一节 |
| **指令是开放的，按钮是封闭的** | 预设的「起草邮件」按钮撤掉，换成「说一句…」 |
| **一个按钮不该断言两件事** | 「做完了」同时说「拿走」和「干完了」，必有一件是假的 |
| **兼容层和改动必须同时落地** | 同上，改列名那次 |
| **记录必须说得清它是什么** | 群发的那句要标明是群发的，否则半年后你以为是专门写的 |
| **对方给了时间锚点的才是真话** | 美国 networking 的规矩，直接改了引擎形状 |
| **形状不是血肉** | 拆模板时最容易分错的一刀 |

## 六、工作方法：一刀一刀砍

**每一刀的节奏是固定的四步**，`docs/` 里 25 份文件全是这么来的：

```
brainstorming  →  设计稿（docs/specs/）  →  施工计划（docs/plans/）  →  实施 → 验收回填
```

几个具体做法，都可以直接教：

**① 设计稿开头永远先写「这一刀解决什么」，而且是写病，不是写功能。**
标题就是病：「红点不再撒谎」「判据推倒重来」「换掉水管，让信自己进来」。

**② 设计稿里必须有一节「明确不做（YAGNI）」和一节「缓办」。**
缓办那节开头都有一句：**「记在这儿，免得这些取舍只活在一次对话里。」**
这是整套方法里最省时间的一条——半个月之后回来，你知道当初为什么没做。

**③ 设计稿是活的，实施过程中当场回改，并标日期。**
比如批量那份稿子里有三处这样的补丁：

> **2026-08-07 改（第一次真跑当天）：进队的判据是「现在需要你」，不是「库里多了行数据」。**
> 真跑第一轮就露馅：某条线提了「8-12 前没回音就跟进」——行动日在 8-12，它 8-6 就吵你。
> **「邮件列表变了」是系统的事件，不是你的事件。**

**④ 旧稿不回改。**
改名那次专门写明：08-01 / 08-03 那三份旧稿和数据库里已有的往来消息**刻意不改**——
「它们是有日期的历史记录，改了就成了篡改。」

**⑤ 验收是一条条打钩的，而且要跑得出数。**
不是「跑通了」，是：

> 迁移前 `select count(*) ... = N`；迁移后**必须还是 N**。
> 3,410 封 / 368 个地址 / 106 个你写过信的 / 2,788 条会话串 / **dropped = 0**。

**⑥ 提交信息写「为什么」，不写「改了什么」。**
130 条提交信息基本都是完整的排查记录：现象 → 查到什么 → 病根 → 判据 → 改法 → 代价 → 顺带发现。半个月后这就是唯一还原得出当时判断的东西。

## 七、护栏：能力和护栏是同一套结构长出来的

这一节是**讲给任何要给 AI 放权的人听的**，也是整个项目最值得单拎出来的设计。

**「不能做」的每一条都是结构上做不到，不是嘱咐它别做：**

| 它做不到 | 为什么做不到 |
|---|---|
| 定稿 | 数据库那头只 grant 了改 `status='draft'` 的行；把 draft 变 final 的函数**压根没 grant 给它** |
| 按发送键 | 发送是一个纯 HTTP 函数，**不在模型的工具白名单里**，只有页面上那颗按钮能触发 |
| 翻你的信箱 | 收信只拉这条线登记过的 thread，**没有「列出所有邮件」的入口** |
| 越线 | 它每个写口的第一个参数都是 `pursuit_id`，**被关在你正打开的那条线里** |

有意思的是，护栏**挪过一次位置，但没有拆**：

- 08-05：「这个系统发不出信」——因为 claude.ai 的 Gmail 连接器**整套工具里根本没有 send**，是能力不存在
- 08-16：「Fairwind 写得出信，但**按不了发送键**」——brain 拿到了 `gmail.send`，但发送函数不在工具白名单里

还有一条实测出来的、必须写死的护栏：

> ⚠️ **2026-08-05 实测发现：Agent SDK 会继承你整台机器的工具配置**——不写 `allowedTools` 的话，它拿得到 Bash、Write、Supabase MCP。
> 那个白名单从「一个稳妥的做法」升级成**必须写死的护栏，一天都不能省**。

以及配套的一条：

> **读可以跨线，写不可以。**
> Fairwind 的价值在「记得」，不在「动」。往后扩它的能力，答案基本都在读的那一侧。
> **它动得越少越好，只要它记得越多。**

## 八、给朋友讲的时候，建议这个顺序

`docs/shots/README.md` 里已经排好了一套 14 张截图的讲述顺序，主线是：**机会从哪来 → 卡里发生什么 → 谁按发送键**。

配合这份回溯，建议这么讲：

1. **先讲 v0**（第二节）—— 让他知道这东西不是凭空设计出来的，是把一个已经在做的人肉流程装上骨架
2. **讲一遍截图**（14 张，20 分钟）—— 让他看见成品
3. **讲三条**（`shots/README.md` 末尾那三条）：
   - 能力和护栏是同一套结构长出来的
   - 绝不丢信息
   - 它做功课，你做决定
4. **然后讲方法**（第六节）—— 这才是他能带走的东西
5. **最后打开 `docs/specs/`** —— 17 份稿子按日期排，让他随便点开一份看：**一刀砍在哪儿、为什么砍在那儿、明确不做什么。**

**要反复强调的一句**（拆家那一刀里的原话）：

> 别人 fork 下来要改的起点，得是**一个有观点的东西**，不是一张白纸。
> 剥掉那些从卡点长出来的形状，剩下的是一个通用机会管理器，**那个东西帮不了任何人。**

所以帮朋友 set up 的正确姿势不是「教他用 Fairwind」，是：
**先问出他自己的卡点，然后一起判断哪些形状要留、哪些要改、哪些要新长。**

## 九、还欠着什么（诚实那一栏）

讲的时候不要藏这些，它们本身就是好素材——**一个天天在用的系统总是欠着东西的。**

- **只在这台 Mac 上有效**。手机开线上地址能看卡、能读记忆，那个框是哑的
- **单人 · 单机 · 无认证**，而且是被结构钉死的（全库没有 `owner_id`、没有 RLS、视图 `grant select to anon`）。真要给别人用，那是单独一轮设计
- **订阅额度共享**，你自己写代码也在烧，会互相抢
- **判断层批注**（定稿时贴一条「你把这个词换了，而面谈里他追问过这段」）——从 08-05 欠到现在
- **构想回流进作品库** —— 现在档案是只进不出的，机会线的成果回不去
- **群发新作品** —— 形状已经对了（`SayTo`），等通讯录导入那一刀
- **brain 上云 / 7×24** —— 逻辑不依赖本机，什么时候搬都行
