## 这一刀解决什么

工具条上四个筛选 tab（[App.jsx:236-241](../../src/App.jsx#L236-L241)）从 08-04 那一刀起就是死的。08-04 稿子写的是「明知是死的，但位置要先占住」。

两天过去，位置还空着。但真正缺的东西也露出来了，而且**不是筛选**：

看板上 26 张新机会、15 张一起写。每一张都要点开、等它想、看一眼、回一句、关掉、点下一张。**这个系统的每一个动作都是单张的。** 你手上有一批性质相同的卡，它逼你一张张来。

所以这一刀做两件事，它们是一件：

1. **批量操作** —— 勾一批卡，对它们一起干一件事。
2. **过卡队列** —— 批量跑完的东西塞进一个队，你左右翻着一张张过完。

第 2 件是第 1 件的必要配套：批处理省的是**跑**，不是**信**。跑出来的每一样东西都还得你过一遍，那就得有个专门过它们的地方。

## 一、工具条：左边镜头，右边动作

```
┌────────────────────────────────────────────────────────────────┐
│ [全部] 待处理  紧急      ⟳ 起草中 3/6      收信 批量操作 造卡任务│
└────────────────────────────────────────────────────────────────┘
   ╰─ 三选一，你选的 ─╯    ╰─ 系统在报 ─╯   ╰─ 你按的 ─╯
```

### 三个筛选（换掉原来四个）

| tab | 依据 | 现成的代码 |
|---|---|---|
| 全部 | 不筛 | — |
| 待处理 | 球在我这边 | [`ballOf(p) === 'me'`](../../src/lib/ball.js) |
| 紧急 | 14 天内截止 / 已过 | [`deadlineLine(p).urgent`](../../src/lib/nextAction.js#L39-L47) |

**为什么原来那四个接不上**：按阶段/按截止/按作品/按来源，说的都是「怎么**排**」。而看板已经按阶段排了——排法只能有一种，所以那四个天生互相打架，接哪一个都要把七列拆掉重画。

新的三个说的是「看**哪些**」。七列照旧，只是变稀。跟排法不冲突，所以它们能活。

筛掉的卡就是不显示。列头的计数跟着变，显示的是**当前视图里的张数**——不是总数。（不然你筛完看见「新机会 26」但下面只有 3 张，那个 26 在骗人。）

**「待处理」大概率很稀。** 08-04 撤掉「从 stage 猜球权」之后，有依据的待处理从 28 张掉到 1 张。这个筛选筛出来可能就那么几张——**那是真的**，不是筛坏了。空视图要说人话：「现在没有球在你这边的线」。

### 进度不并进 tab 组

「起草中 3/6」是**系统在跟你报告**：不能点、随时会消失、没有选中态。挤进那一组它就成了第四个看着能点的 tab。

隔开放，灰字带转圈，一眼是两种东西。

### 右边三个动作

| 按钮 | 要不要选卡 | 性质 |
|---|---|---|
| **收信** | 不选，所有线都收 | 机械。不用你在场 |
| **批量操作** | 进选择模式 | 选完才出现动作 |
| **造卡任务** | — | 原样不动 |

**收信为什么不进选择模式**：08-05 §1 按「要不要你在场」把事情切成进货和加工。收信是唯一不用你在场的——拉登记过的 thread，跑完只是多几封信，不改任何判断，跑错了也不留痕。让它跟起草共用一个选择流程，是把一件零风险的事按住了。

没登记 thread 的线就空着，**不报错、不弹窗**。

## 二、选择模式

点「批量操作」，看板上每张卡冒出勾选框，工具条换脸：

```
┌────────────────────────────────────────────────────────────────┐
│ [全部] 待处理  紧急    已选 6 张（3 张不在当前视图）           │
│                              起草邮件   定下一步      取消     │
└────────────────────────────────────────────────────────────────┘
```

### 切镜头不清空勾选

你筛「紧急」勾了 6 张，切回「全部」——那 6 张还算数。

反过来做的话，你切一下视图，勾了半天的东西无声无息就没了。那是「**看不见 = 丢了**」（08-04 血的教训）的近亲。

但也不能假装它们都在眼前，所以工具条照实说：`已选 6 张（3 张不在当前视图）`。

### 一叠（Stack）怎么勾

[Pipeline.jsx](../../src/components/Pipeline.jsx) 里同一个造卡任务出来的卡会折成一叠。叠头上给一个勾选框，勾它 = 勾这一叠里全部。半选状态显示 indeterminate。

**这是「找 workshop 机构 · 15 张」那种场景真正的入口**——冷邮件本来就是一批一批起的。

### 批量换列不做

原本想过。你说不需要，撤。

## 三、两个批量动作

### 3.1 起草邮件

每条选中的线各起一版，落成一份 `deliverables` 行（`kind='email'`、`status='draft'`），对话里留一条锚点。

**不问「这条线聊过没有」。** 一度想加这道闸，判错了：料一直都在——`pending` 里的卡后台早读透了（[brain/server.js](../../brain/server.js) 每 60 秒扫）、档案里 59 条弹药、匹配过的作品、往来的信。你勾了它，就是你判断该起了。

换成一件更有用的事：**每份草稿交代料从哪来**。[0027](../../supabase/migrations/0027_deliverables_and_threads.sql) 里 `deliverables.source` 这个字段就是为这个留的。

```
Web Residency No.22 · 回信                          草稿
────────────────────────────────────────────────────
收件人  Kirk <kirk@…>
主题    Re: 入围通知

Dear Kirk, Thank you for…
────────────────────────────────────────────────────
料：8/5 你定的「主打 ECR，保留 Persona 线」+ 8/3 他那封信
```

一眼看得出这版是从哪儿拼的，比一个「够不够格」的判定有用得多——后者只有过和不过两档，前者告诉你**该不该信它**。

#### 冷邮件：先找收件人

冷外联的线常常还没有联系人邮箱。Fairwind 有 `WebSearch`/`WebFetch`，让它去找。

但**搜到的邮箱是未核实的事实**，不能直接写进 `contacts`：

```
收件人  info@kunsthal.nl   ⚠ 网上搜到的，没核实      改
────────────────────────────────────────────────────
料：档案里的英文 bio（一字未改）+ 机构主页的 workshop 页
```

未核实的记号一直挂着，直到你改或你认。**定稿时规则层拦一下**——[rules.js](../../src/lib/rules.js) 加一条 check：收件人未核实 → 定稿是灰的。

这条必须是闸，不能靠你记得。规则层的定义就是「数出来的，不是判断出来的」（[rules.js:1-8](../../src/lib/rules.js#L1-L8)）——「这个邮箱有没有被人确认过」是个布尔值，数得出来。

搜不到就空着，草稿照起。空收件人同样定不了稿。

### 3.2 定下一步

批量给选中的线写 `next_action`（含「该碰的日子」`next_touch_at`）。

**这是这一刀里唯一会写假话的动作**，得单独说清楚。

`next_action` 是卡上最显眼的一行——[nextAction.js:53-68](../../src/lib/nextAction.js#L53-L68) 里它压过截止、压过「该碰一下」，是卡上唯一说得出「做什么」的东西。批量跑一次能造 26 条。

而 08-05 §6.2 末尾那条 ⬜ 刚写过：

> **假的待办比没有待办更坏。**

所以两道：

**第一道：标明是它提的。** 写进去的行带一个「它提的」记号，卡上、抽屉里都看得见。你在过卡器里点过头，记号消失。没点头之前，你一眼知道这句话还没人认过。

这需要一列新字段——`pursuits.next_action_by`（`you` | `fairwind`），跟 `deliverables.created_by` 同一个意思。**不能靠 `✨` 之类的文本前缀混在 `next_action` 里**：那样「谁提的」就成了正文的一部分，改一次文案全库要迁移，而且前端得靠字符串匹配来认。一个字段一种意思——[0019](../../supabase/migrations/0019_next_action.sql) 那一刀立的规矩，起因正是 `next_touch_at` 被拿来装四种意思、于是卡上经常说错话（[nextAction.js:1-9](../../src/lib/nextAction.js#L1-L9)）。

`next_action_by='fairwind'` 且你没认过 → 记号在。你点「好了」→ 改成 `you`，记号消失。

**第二道：说得出依据的才写。** 没有信、没有截止、没有球权信号的线，它该说「这条线我没有依据，没提」——而不是编一句「跟进一下」。

第二道是硬的。这跟 08-04 撤掉「从 stage 猜球权」是同一件事：

> **宁可不说，也不猜。**

代价会跟那次一样看得见：你勾 20 张，可能只有 6 张真写上了。那消失的 14 张本来就没有依据。

#### 为什么起草不设闸而定下一步设

两个动作的输入是两种东西：

| | 输入 | 没有会怎样 |
|---|---|---|
| 起草 | **素材**（brief、档案、往来） | 素材一直都在，起得出来 |
| 定下一步 | **状态**（信、截止、球权） | 没状态就只能猜「这条线现在该干什么」 |

起草是用素材造东西，定下一步是**断言这条线现在的处境**。断言需要依据，造东西不需要。

## 四、结果落在哪

> **对话是动词，产出是名词。**（08-05 §4）

| 动作 | 落进对话（`pursuit_messages`） | 落进别处 |
|---|---|---|
| 起草邮件 | 一条锚点：「起好了，在右边 →」 | `deliverables` 一行（draft） |
| 定下一步 | 一条：「我看下一步该 ⋯⋯，依据是 8/5 那封信」 | `pursuits.next_action` / `next_touch_at` |
| 收信 | 每封新信一条 `kind='email'` | 附件进 `attachments` |

**草稿正文为什么不直接塞进对话流**：塞进聊天记录里就编辑不了、也定不了稿，你只能复制出来。它必须是一份产出，才有「定稿」这个动作可按。对话里留锚点是为了**它出自哪段商量点得回去**。

## 五、过卡队列

批处理跑完，卡进队。你左右翻着一张张过。

### 5.1 就是抽屉，给它加个队列

**不新建界面。** 看板上点一张卡右边划出的抽屉（[App.jsx:272-285](../../src/App.jsx#L272-L285)）干的就是这件事——代码注释写得很直白：「你要的就是一张接一张地过」。区别只在于它的队列长度永远是 1，而且关掉就没了。

```
┌─ 抽屉 ────────────────────────────────┐
│  ‹  3 / 6  ›              收起    ✕   │
├───────────────────────────────────────┤
│  Web Residency No.22                  │
│  ─────────────────────────────────    │
│  这次要你过的那份                     │
│  ┌─────────────────────────────────┐  │
│  │ 收件人 Kirk <kirk@…>            │  │
│  │ Dear Kirk, Thank you for…       │  │
│  └─────────────────────────────────┘  │
│  料：8/5 你定的「主打 ECR」+ 8/3 他那封信│
│  ─────────────────────────────────    │
│  对话（可以接着跟它说）               │
│  ⋯                                    │
│  ─────────────────────────────────    │
│  [ 好了 ]        [ 这张先放着 ]       │
└───────────────────────────────────────┘
```

**队列模式下抽屉多一段**：最上面是**这次跑出来的东西**，下面才是对话。不在队列里的时候（点单张卡）这一段不出现，抽屉跟今天一模一样。

这一段装什么，看这张卡是被哪个动作送进队的：

| 送它进队的动作 | 最上面那段是 |
|---|---|
| 收信 | 这次新到的那几封信（原文可展开） |
| 起草邮件 | 草稿正文（可编辑）+ 料从哪来 |
| 定下一步 | 它提的那句 + 依据 |

整页（`?p=<id>`）的三栏不动，那是另一个档位。

### 5.2 什么算过完了

**翻过去不算。** 翻回来它还在。

两个出口，都出队：

| 出口 | 干什么 |
|---|---|
| **好了** | 草稿定稿 / 那句下一步你认了（记号消失） |
| **这张先放着** | 不认也不改。东西留在库里——草稿还在右栏，「它提的」 记号还挂着 |

**顶栏那个数字只降在你动了手的时候。** 一路 `› › ›` 翻到底，队还是 6 张。

这条是整个队列诚不诚实的地基。做成「看一眼就算」，那个数字从此只能告诉你「看没看过」，不能告诉你「干没干完」——而你要问的是后者。

### 5.3 顶栏入口

```
Fairwind   项目争取  人际管理  我的档案        ▣ 过卡 · 5
```

- 队空的时候**整个按钮不渲染**。不显示「过卡 · 0」——那是占位，这一刀刚撤掉四个。
- 收起 ≠ 丢弃。点回来接着上次那张。

### 5.4 队列存哪

`localStorage`，跟 [`pa_seen`](../../src/App.jsx#L34-L36) 一样，也跟着 `storage` 事件跨标签页同步。刷新还在。

**不上库。** 它是「你这台机器上手头这摊活」，不是事实。事实（草稿、next_action、信）全都已经在库里了——队列丢了，一样东西都不会消失，只是要你自己去看板上找。

存的是 `[pursuit_id]` 加一个「这次是什么动作」的标签，**不存内容**。内容永远从库里读。

### 5.5 单张卡还是老样子

点看板上一张卡 = 队列长度 1，`‹ 1/1 ›` 那排不显示。跟今天完全一样。**不重做已经好用的东西。**

## 六、跑的时候

6 张卡串行跑 brain，每张十几秒——一两分钟。

- **界面不锁。** 工具条上显示 `⟳ 起草中 3/6`，看板照常能点、能拖。
- 跑完顶栏冒出「过卡 · 6」。
- **跑挂了要在 [Trouble](../../src/components/Trouble.jsx) 那条上说话。** 08-05 §6.7：静默失败是最坏的情况，这病犯过一次（「讲懂」改后台之后整整一天没有一张新卡被读过，谁也没发现）。
- 单张失败不拖累整批：那张不进队，Trouble 上记一笔「3 张起草失败」。

## 七、分三刀

这三件事互相不锁死，建议分开走：

| 刀 | 做什么 | 为什么这个顺序 |
|---|---|---|
| **一** | 三个筛选 tab 接上 + 「收信」全局按钮 + 队列抽屉 + 顶栏入口 | 收信是唯一零风险的动作，**拿它把队列这套东西跑通**——收到新信的线进队，你翻着过。队列的诚实性（什么算过完、数字准不准）在这一刀验完 |
| **二** | 选择模式 + 批量起草邮件（含找收件人 + 未核实闸） | 队列已经能用了，这一刀只管「怎么选」和「起草」 |
| **三** | 批量定下一步（两道闸 + 「它提的」 记号） | 最容易写假话的一个，放最后。前两刀跑过之后你才知道它到底有多爱猜 |

第一刀不依赖任何新表。第二刀要 `deliverables` 能在抽屉里编辑和定稿（08-05 已经做了整页三栏的版本，抽屉那份要补）。第三刀只动 `pursuits` 两个现成字段。

## 八、明确不做（YAGNI）

- **原来那四个筛选 tab。** 撤掉，不留位。它们说的是「怎么排」，跟看板已经按阶段排了这件事天生打架。*空着可以，假着不行。*
- **批量换列 / 批量暂停。** 拖拽已经能做，量大的时候再说。
- **批量发信。** Gmail 连接器里根本没有 send（08-05 §9）。
- **队列上库 / 跨设备。** 它是手头这摊活，不是事实。
- **多选筛选（待处理 + 紧急同时开）。** 三选一。真需要交叉的时候会自己冒出来。
- **批处理的撤销。** 起草出来的是草稿（不会自己发出去），下一步带记号（一眼认得出没认过）——两样都不需要一个全局撤销键。

## 缓办

| | 为什么等 |
|---|---|
| 队列里混装不同动作 | 第一刀只有收信，第二刀只有起草。混装（一队里既有草稿又有下一步）等真的同时跑过再说 |
| 批处理排队 / 并发 | 先串行。6 张一两分钟能忍，真嫌慢再谈 |
| 从筛选结果一键全选 | 先手勾。勾累了自然会知道该加在哪 |
| 收件人核实之后回流进 `contacts` | 等真有一批冷邮件发出去 |
