## 这一刀解决什么

工具条上四个筛选 tab（[App.jsx:236-241](../../src/App.jsx#L236-L241)）从 08-04 那一刀起就是死的。当时写的是「明知是死的，但位置要先占住」。

两天过去，位置还空着。但真正缺的东西也露出来了，而且**不是筛选**。是三件：

### 一、这个系统的每一个动作都是单张的

看板上 26 张新机会、15 张一起写。每一张都要点开、等它想、看一眼、回一句、关掉、点下一张。你手上有一批性质相同的卡，它逼你一张张来。

### 二、没有人回头看新信让哪些待办作废了

08-05 那份稿子末尾留了一条没做的 ⬜，是第一次真的收信当场撞出来的：

> 那次收信收到了 8/5 CultureHub 的回信——LOA 日期已改好、等签字。于是卡上两样东西当场过期了：`next_touch_at = 8/7`（「没回就催」，人家回了）和右栏那份《催 Mattie · LOA 还没回》。**「自动立项」得配一个「自动过期」**，否则跑得越久，卡上假的待办越多——而假的待办比没有待办更坏。

**收信只是把新事实搬进来，没有人消化它。**

### 三、没有一个地方装「手头这摊活」

批处理省的是**跑**，不是**信**。跑出来的每一样东西都还得你过一遍。而现在过一张卡的地方（抽屉）关掉就没了，没有"还剩几件没干"这回事。

三件事的答案是三个东西，各自对上一件：

| | 做什么 |
|---|---|
| **更新最新信息** | 收信 → 清过期 → 重提下一步。一个按钮，全局 |
| **批量操作** | 勾一批卡，一起起草邮件 |
| **过卡队列** | 一份待办。上面两个往里塞，你一张张过完 |

## 一、工具条：左边镜头，右边动作

```
┌──────────────────────────────────────────────────────────────────────┐
│ 待处理  紧急         ⟳ 更新中 3/40      更新最新信息 批量操作 造卡任务│
└──────────────────────────────────────────────────────────────────────┘
  ╰─ 两个开关 ─╯      ╰─ 系统在报 ─╯      ╰────── 你按的 ──────╯
```

### 1.1 两个开关，不是三选一

原来那四个 tab（按阶段/按截止/按作品/按来源）**撤掉，不留位**。

**为什么它们两天都接不上**：这四个说的都是「怎么**排**」。而看板已经按阶段排了——排法只能有一种，所以这四个天生互相打架，接哪一个都要把七列拆掉重画。

换成两个说「看**哪些**」的开关。七列照旧，只是变稀：

| 开关 | 依据 | 现成的代码 |
|---|---|---|
| **待处理** | 球在我这边 | [`ballOf(p) === 'me'`](../../src/lib/ball.js) |
| **紧急** | 14 天内截止 / 已过 | [`deadlineLine(p).urgent`](../../src/lib/nextAction.js#L39-L47) |

**两个可以同时按下去**，因为真正有用的恰恰是交叉：

- 都不按 = 全部（所以没有「全部」这个 tab——它就是"什么都不按"，单列一个反而多余）
- 只按「紧急」= 快到期的**都算**，球不在你这边的也算。对方压着没回、眼看要过期，那是该催的
- **两个都按** = 球在我这边而且快到期 = 最该现在动的那批

筛掉的卡就是不显示。列头计数跟着变，显示的是**当前视图里的张数**——不是总数。（不然你筛完看见「新机会 26」下面只有 3 张，那个 26 在骗人。）

**「待处理」大概率很稀。** 08-04 撤掉「从 stage 猜球权」之后，有依据的待处理从 28 张掉到 1 张。这个开关按下去可能就那么几张——**那是真的**，不是筛坏了。空视图要说人话：「现在没有球在你这边的线」。

### 1.2 进度不并进开关组

「⟳ 更新中 3/40」是**系统在跟你报告**：不能点、随时会消失、没有选中态。挤进开关那一组它就成了第三个看着能点的按钮。

隔开放，灰字带转圈，一眼是两种东西。

### 1.3 右边三个动作

| 按钮 | 要不要选卡 | 会不会改库 |
|---|---|---|
| **更新最新信息** | 不选，所有线 | **会**（见第二节） |
| **批量操作** | 进选择模式 | 会（建草稿） |
| **造卡任务** | — | 原样不动 |

## 二、更新最新信息

一个按钮，三步，**顺序不能反**：

```
① 收信 ──→ ② 清过期 ──→ ③ 重提下一步
```

不收信就不知道什么过期了；不清过期就会在假前提上提下一步。

| | 干什么 | 例子 |
|---|---|---|
| ① 收信 | 每条登记过 thread 的线拉新消息（08-05 §6，**永远不遍历信箱**） | CultureHub 收回 4 封 |
| ② 清过期 | 新信让哪些待办作废，划掉 | 「8/7 没回就催 LOA」——他 8/5 回了 |
| ③ 重提下一步 | 现在这条线该干什么 | 「LOA 日期改好了，等你签字」 |

没登记 thread 的线，①什么都不做，**不报错、不弹窗**。

> **2026-08-06 收窄（实施前定的）：②③只在「这次①真收到新信」的线上跑。**
> 没有新信 = 没有新事实 = 一个字都不写。原来的设计是②③照跑所有线，
> 靠「说得出依据才写」那道闸拦凑数——现在直接把闸变成范围：**它只消化事实，
> 不主动巡逻**。在没变化的线上编一句凑数的话，哪怕只发生一次，这个按钮就不可信了。
>
> ①的范围不变：**所有**登记过 thread 的线都收，包括「谈成」「暂停处理」
> ——CultureHub 恰恰在谈成里、而且是信最活跃的一条。收信零风险，不用省。

### 2.1 为什么这三步必须是一个按钮

一度设计成「收信」单独一个按钮。那正是 08-05 撞上的病：**信收进来了，但没人回头看这些信让哪些待办作废了。** 收信而不消化，跑得越久卡上假的待办越多。

它们是一件事的三个瞬间，中间没有真正的停顿——跟 08-04 把「批准 + 挑作品」并成一列是同一个判据。

### 2.2 清过期：唯一会让信息消失的一步

这个库的第一条铁律：**已有信息不许消失、不许不可见。**（08-04 血的教训：*看不见 = 丢了*）

所以「清过期」**划掉，不删掉，而且说出因为哪封信**：

```
✗ 8/7 没回就催 LOA
   作废于 8/6 · 因为他 8/5 回信了 →
```

那个 `→` 点得回到那封信（左栏往来）。你翻到这张卡，看得见"这条待办本来在，被这封信作废了"——不是它凭空没了。

数据上要两列新字段：

```sql
alter table producer.pursuits
  add column next_action_void_at timestamptz,     -- 什么时候作废的
  add column next_action_void_by uuid;            -- 因为哪条消息（pursuit_messages.id）
```

**跟 `next_action_done_at` 分开。做完了和作废了是两回事**——混一个字段又是「一个字段装两种意思」那个病（[0019](../../supabase/migrations/0019_next_action.sql) 治过一次，起因就是 `next_touch_at` 被拿来装四种意思、于是卡上经常说错话，见 [nextAction.js:1-9](../../src/lib/nextAction.js#L1-L9)）。

[actionLine()](../../src/lib/nextAction.js#L53-L68) 里判断「有没有待办」的条件跟着加一个 `!p.next_action_void_at`。

### 2.3 重提下一步：这一刀唯一会写假话的地方

`next_action` 是卡上最显眼的一行——actionLine 里它压过截止、压过「该碰一下」，是卡上唯一说得出「做什么」的东西。

**这个按钮一下能给好几条线写 `next_action`**（收窄后只碰有新信的线，但一次收信可能十几条线都有动静）。所以两道闸不是「好设计」，是**必须**：

#### 第一道：标明是它提的

```sql
alter table producer.pursuits
  add column next_action_by text not null default 'you';   -- you | fairwind
```

`next_action_by='fairwind'` → 卡上、抽屉里那行带一个「它提的」记号。你在过卡器里点了「做完了」/ 认了它，改成 `you`，记号消失。**没认之前你一眼知道这句话还没人认过。**

不能拿 `✨` 之类的文本前缀混在 `next_action` 正文里——那样「谁提的」成了正文的一部分，改文案要迁移全库，前端得靠字符串匹配来认。

#### 第二道：说得出依据的才写

没有信、没有截止、没有球权信号的线，它该说「这条线我没有依据，没提」——而不是编一句「跟进一下」。

跟 08-04 撤掉「从 stage 猜球权」是同一件事：

> **宁可不说，也不猜。**

代价会跟那次一样看得见：40 条线跑下来可能只有 6 条真写上了。那消失的 34 条本来就没有依据。

**已经有 `next_action` 且没作废的线，不覆盖。** 你自己写的那句永远优先。

### 2.4 什么才配进过卡队列

> **2026-08-07 改（第一次真跑当天）：进队的判据是「现在需要你」，不是「库里多了行数据」。**
> 原设计是收到新信 / 作废 / 提案一律进队。真跑第一轮就露馅：Paperbark 提了
> 「8-12 前没回音就跟进」——行动日在 8-12，它 8-6 就吵你。
> **「邮件列表变了」是系统的事件，不是你的事件。**

三条判据，对上三种「需要你」：

| # | 什么进队 | 机制 |
|---|---|---|
| 1 | **对方来信**（`role='org'` 的新信） | 你自己发的信被收录进档案**不惊动你**——你知道你发过。除非它连带触发了 2 或 3 |
| 2 | **行动时间到了** | 该碰日 ≤ 今天，或截止进 14 天窗口且球在你。纯前端可算，开页面时扫一遍、每轮更新后扫一遍——**到日子的卡自己来找你**，不用你扫看板 |
| 3 | **有话跟你说** | 待办被作废（得告诉你因为哪封信）；提案**只有现在就能动的**（无日期或日期 ≤ 今天）才进队——带未来日子的提案只写卡、闭嘴，到日子由 2 接手 |

两个诚实性细节：

- 到日子进的队（`via='due'`）**不清你放过的记号**——不然每天开页面「先放着」的全弹回来。对方来信进的队（`via='update'`）清记号，因为它真的变了。
- 「做完了」只出队，不替你办事。你没真去动那条线，下次开页面它还会回来——**那是对的**，队列不陪你骗自己；真做了的话卡上勾掉那一下自然让它不再符合判据。

进队之外，这轮改了什么仍然全部可见：信在左栏、作废行划在卡上、提案带记号——**队列不是唯一的交代，只是「现在需要你」的那部分。**

### 2.5 跑的时候

40 条线串行跑，一条十几秒——几分钟。

- **界面不锁。** 工具条上 `⟳ 更新中 3/40`，看板照常能点、能拖
- 跑完顶栏冒出「过卡 · N」
- **跑挂了要在 [Trouble](../../src/components/Trouble.jsx) 那条上说话。** 08-05 §6.7：静默失败是最坏的情况，这病犯过一次（「讲懂」改后台之后整整一天没有一张新卡被读过，谁也没发现）
- 单条失败不拖累整批：那条不进队，Trouble 上记一笔「3 条更新失败」

## 三、批量操作

点「批量操作」，看板上每张卡冒出勾选框，工具条换脸：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 待处理  紧急   已选 6 张（3 张不在当前视图）  起草邮件  过一遍  取消 │
└──────────────────────────────────────────────────────────────────────┘
```

**只有两个动作。**「定下一步」不在这儿——它是「更新最新信息」的第 3 步，全局跑，不用你圈范围。

| 动作 | 干什么 |
|---|---|
| **起草邮件** | 每条选中的线各起一版（下面 3.2） |
| **过一遍** | 不跑任何东西，直接把选中的塞进过卡队列 |

「过一遍」是筛选和过卡器之间那条路：**筛选是镜头，过卡器是工作台，「过一遍」是把镜头里的东西端上台。** 按下「待处理 + 紧急」，勾出真该现在动的那几张，端上去挨个干完。

### 3.1 切镜头不清空勾选

你按着「紧急」勾了 6 张，松开开关——那 6 张还算数。

反过来做的话，你切一下视图，勾了半天的东西无声无息就没了。那是「看不见 = 丢了」的近亲。

但也不能假装它们都在眼前，所以工具条照实说：`已选 6 张（3 张不在当前视图）`。

### 3.2 起草邮件

每条选中的线各起一版，落成一份 `deliverables` 行（`kind='email'`、`status='draft'`），对话里留一条锚点。

**不问「这条线聊过没有」。** 一度想加这道闸，判错了：料一直都在——`pending` 里的卡后台早读透了（[brain/server.js](../../brain/server.js) 每 60 秒扫）、档案里 59 条弹药、匹配过的作品、往来的信。你勾了它，就是你判断该起了。

换成一件更有用的事：**每份草稿交代料从哪来**。[0027](../../supabase/migrations/0027_deliverables_and_threads.sql) 里 `deliverables.source` 就是为这个留的。

```
Web Residency No.22 · 回信                          草稿
────────────────────────────────────────────────────
收件人  Kirk <kirk@…>
主题    Re: 入围通知

Dear Kirk, Thank you for…
────────────────────────────────────────────────────
料：8/5 你定的「主打 ECR，保留 Persona 线」+ 8/3 他那封信
```

一眼看得出这版是从哪儿拼的，比一个「够不够格」的判定有用得多——后者只有过和不过两档，前者告诉你**该不该信它**。

#### 冷邮件：先找收件人

冷外联的线常常还没有联系人邮箱。Fairwind 有 `WebSearch`/`WebFetch`，让它去找。

但**搜到的邮箱是未核实的事实**，不能直接写进 `contacts`：

```
收件人  info@kunsthal.nl   ⚠ 网上搜到的，没核实      改
────────────────────────────────────────────────────
料：档案里的英文 bio（一字未改）+ 机构主页的 workshop 页
```

记号一直挂着，直到你改或你认。**定稿时规则层拦一下**——[rules.js](../../src/lib/rules.js) 加一条 check：收件人未核实 → 定稿是灰的。

这条必须是闸，不能靠你记得。规则层的定义就是「数出来的，不是判断出来的」（[rules.js:1-8](../../src/lib/rules.js#L1-L8)）——「这个邮箱有没有被人确认过」是个布尔值，数得出来。

搜不到就空着，草稿照起。空收件人同样定不了稿。

### 3.3 一叠（Stack）怎么勾

[Pipeline.jsx](../../src/components/Pipeline.jsx) 里同一个造卡任务出来的卡会折成一叠。叠头上给一个勾选框，勾它 = 勾这一叠全部，半选显示 indeterminate。

**这是「找 workshop 机构 · 15 张」那种场景真正的入口**——冷邮件本来就是一批一批起的。

### 3.4 批量换列不做

拖拽已经能做，量大的时候再说。

## 四、结果落在哪

> **对话是动词，产出是名词。**（08-05 §4）

| 动作 | 落进对话（`pursuit_messages`） | 落进别处 |
|---|---|---|
| 收信 | 每封新信一条 `kind='email'` | 附件进 `attachments` |
| 清过期 | 一条：「这条待办作废了，因为他 8/5 回信了」 | `next_action_void_at` / `_by` |
| 重提下一步 | 一条：「我看下一步该 ⋯⋯，依据是 8/5 那封信」 | `next_action` + `next_action_by='fairwind'` |
| 起草邮件 | 一条锚点：「起好了，在右边 →」 | `deliverables` 一行（draft） |

**草稿正文为什么不直接塞进对话流**：塞进聊天记录里就编辑不了、也定不了稿，你只能复制出来。它必须是一份产出，才有「定稿」这个动作可按。对话里留锚点是为了**它出自哪段商量点得回去**。

## 五、过卡队列

### 5.1 它是一份待办，不是一趟班次

**没做完的一直在。** 顶栏那个数字说的是一句实话：**你还欠着几件事。**

一度设计成「一轮」（按下那一刻定 7 张，干完这轮就散）。不对——你干不完的时候它就该赖着。

### 5.2 就是抽屉，给它加个队列

**不新建界面。** 看板上点一张卡右边划出的抽屉（[App.jsx:272-285](../../src/App.jsx#L272-L285)）干的就是这件事——代码注释写得很直白：「你要的就是一张接一张地过」。区别只在于它的队列长度永远是 1，而且关掉就没了。

```
┌─ 抽屉 ────────────────────────────────┐
│  ‹  3 / 6  ›              收起    ✕   │
├───────────────────────────────────────┤
│  Web Residency No.22                  │
│  ─────────────────────────────────    │
│  这次要你过的那份                     │
│  ┌─────────────────────────────────┐  │
│  │ 收件人 Kirk <kirk@…>            │  │
│  │ Dear Kirk, Thank you for…       │  │
│  └─────────────────────────────────┘  │
│  料：8/5 你定的「主打 ECR」+ 8/3 那封信 │
│  ─────────────────────────────────    │
│  对话（可以接着跟它说）               │
│  ⋯                                    │
│  ─────────────────────────────────    │
│  [ 做完了 ]      [ 再等一等 ]         │
└───────────────────────────────────────┘
```

**队列模式下抽屉多一段**：最上面是这次跑出来的东西，下面才是对话。不在队列里的时候（点单张卡）这一段不出现，抽屉跟今天一模一样。

这一段装什么，看这张卡是被什么送进队的：

| 送它进队的 | 最上面那段是 |
|---|---|
| 收到新信 | 这次新到的那几封（原文可展开） |
| 待办被作废 | 划掉的那条 + 因为哪封信 |
| 被提了新下一步 | 它提的那句 + 依据 |
| 起草邮件 | 草稿正文（可编辑）+ 料从哪来 |
| 「过一遍」端上来的 | 什么都不加，就是这张卡本身 |

整页（`?p=<id>`）的三栏不动，那是另一个档位。

### 5.3 两个出口

| 出口 | 队里 | 顶栏数字 | 下次「更新最新信息」 |
|---|---|---|---|
| **做完了** | 拿走 | **降** | 不会再来（草稿定稿了 / 那句下一步认了 / 你自己端上来的那张，你说完了就完了） |
| **再等一等** | **留着**，挪到队尾 | 不降 | 还在，**不重复塞一份** |

**翻过去（`›`）不算。** `›` 是翻页，什么都没发生，翻回来它原样在那儿。

**「再等一等」跟 `›` 不是一回事**：它是你看过了、决定现在不动。那张卡打上记号 `8/6 你先放着了`，翻回去看得见。

挪到队尾是为了这一轮不再挡你。要是剩下的你全放过了，抽屉说人话然后停手，**不无限转圈**：

```
┌───────────────────────────────────────┐
│  剩下 3 张这轮你都先放着了            │
│  它们还在队里，明天再来               │
│              [ 收起 ]                 │
└───────────────────────────────────────┘
```

### 5.4 不重复塞

已经在队里的卡，「更新最新信息」跑第二次是**更新它那一份**，不是再插一张。

不然跑三次同一条线在队里躺三份，那个数字立刻就没意义了。

### 5.5 顶栏入口

```
Fairwind   项目争取  人际管理  我的档案        ▣ 过卡 · 5
```

- 队空的时候**整个按钮不渲染**。不显示「过卡 · 0」——那是占位，这一刀刚撤掉四个
- 收起 ≠ 丢弃。点回来接着上次那张

### 5.6 队列存哪

`localStorage`，跟 [`pa_seen`](../../src/App.jsx#L34-L36) 一样，也跟着 `storage` 事件跨标签页同步。刷新还在。

**不上库。** 它是「你这台机器上手头这摊活」，不是事实。事实（新信、草稿、next_action、作废记录）全都已经在库里了——队列丢了，一样东西都不会消失，只是要你自己去看板上找。

存的是 `[{ pursuit_id, 什么送它进来的, 你放过没有 }]`，**不存内容**。内容永远从库里读。

### 5.7 单张卡还是老样子

点看板上一张卡 = 队列长度 1，`‹ 1/1 ›` 那排不显示。跟今天完全一样。**不重做已经好用的东西。**

## 六、分三刀

| 刀 | 做什么 | 为什么这个顺序 |

## 七、明确不做（YAGNI）

- **原来那四个筛选 tab。** 撤掉，不留位。它们说的是「怎么排」，跟看板已经按阶段排了这件事天生打架。*空着可以，假着不行。*
- **批量换列 / 批量暂停。** 拖拽已经能做。
- **批量发信。** Gmail 连接器里根本没有 send（08-05 §9）。
- **队列上库 / 跨设备。** 它是手头这摊活，不是事实。
- **批处理的撤销。** 起草出来的是草稿（不会自己发出去）、下一步带「它提的」记号、作废的划掉还看得见——三样都留着痕，不需要一个全局撤销键。
- **过卡队列里的排序。** 先按进队顺序。放过的挪队尾是唯一的例外。
