# 你说一句，Fairwind 判该记成什么

> 日期：2026-09-11。状态：**设计稿**。
> 接在 [9/4 聊天拨状态机](2026-09-04-chat-moves-the-state-design.md) 后面，把那套推到所有状态；
> 顺手把见面复盘那格的双判去掉；「记一笔」按钮退场。
>
> **指代**：**你** = Di Hu；**对方** = 线另一头的真人；**Fairwind** = agent。

---

## 〇、起因

他 9/11 问：「我每次给 Fairwind 发信息，它反正也得跑脑子，顺便看一下有没有要
提取进事件和记忆的事情不就行了？记一笔按钮能不能直接去掉？会很贵吗？」

查了库：**已经在这么做了，但只做了一格**。线在 DEBRIEF（约的见面过了）时，你说的
下一句，脑子先问一次「见成了吗」，成了就把你的原话记成 meet 笔（`handleChat` 那段）。
Huntington 9/3、Book Arts 9/4、Descanso 9/11 三条 meet 笔都是这么来的。别的状态下
你说什么都不会自动记。

而且 Descanso 那句判了两遍：复盘那格记完 meet 笔，盲格子又花一次调用判这条笔
「是不是见面的下文」，同一次回复里 Fairwind 自己又报了 [[STATE]] 起新等待。
一遍带全卷宗，一遍盲的。

钱不是问题：你每句话脑子本来就带全卡跑一次，「顺便判」是同一次回复末尾多一行
信封，几十个输出 token；规矩在静态块里按缓存价读。

## 一、原则

- **笔有两种：事件和记忆。** 事件动状态机（一封信、见了面、办完了一件事），
  记忆不动（他是我老师、她不爱接电话）。今天它们挤在同一个「记一笔」按钮里。
- **同一件事只判一次，由带全卷宗的那个判。** 你在聊天里说的，Fairwind 当场判；
  它落的笔自带标签，盲格子不再排队重判。盲格子只剩一件事：判脑子没开时你直接
  记的笔。
- **原话进笔。** 事件笔和记忆笔的正文都是你说的那句，不是它的转述。这条跟
  「agent 不模仿他写信」是同一条红线。
- **默认落地，按了能撤回**（9/4 定的）。每种落法都有小卡和撤回。
- **商量不算往来。** 聊天本身仍不是事实；事实是它摘出来、你没撤的那条。

## 二、三个去处

Fairwind 读完你那句，三选一（也可以两个信封同出：一条既是事件又值得记）：

| 你说的 | 去处 | 信封 | 落成什么 |
|---|---|---|---|
| 打了没接 / 表单交了 / 见完了 / 周四再催 / 不用等了 | **事件** | `[[STATE]]`（已有，多一种 `met`） | 一条笔（正文 = 你的原话）+ 标签，状态当场变 |
| 他是我 CalArts 的老师 / 她不爱接电话 / 资助只报销机票 | **记忆** | `[[MEMO]]`（新） | 线上一条 memo 笔（不算事件），或这个人的关系记忆末尾追加一段 |
| 你觉得这封怎么写 / 帮我看看官网 | 商量 | 无 | 什么都不记 |

### `[[STATE]]` 的变化

- 新拨法 **`met`**：见成了。落一条 **kind='meet'** 的笔（不是 decision），标签
  `resolves=true`，关掉 DEBRIEF / MEETING_SET；48 小时信、回谢介绍人照旧从这条
  meet 笔长出来（0097 那两支不动）。
- 所有从聊天来的 STATE 笔，**正文 = 你刚说的那句**（`p_text`）；小卡那行字进
  `gist` 和 meta。到点起草那条路没有你的话，正文照旧是「聊天里定的：…」。
- 视图里关见面的判据多认两种：`situation like '聊天里定的：met%'`、
  `'聊天里定的：done%'`（原来只认 MEETING_SET% / DEBRIEF% / 已处理按钮）。

### `[[MEMO]]`

```
[[MEMO]] {"to":"line"|"person","text":"要记的那句（用他的原话，可以截短，不改写）"}
```

- `to='line'`：这条线上一条 **kind='memo'** 的笔。memo 不在 `note|meet|decision`
  里，所以 v_pa_state 不把它当事件（不关「该你回」），`pa_facts_to_judge` 也不收它。
  时间线上照常显示，标签叫「记忆」。
- `to='person'`：**只在你正跟一个人聊时**（owner 是 contact）。追加到
  `contacts.notes` 末尾（换行 + 原句），旧值存进气泡 meta，撤回长回旧值。
  跟线聊时说的人的事，一律进线的 memo —— 不让它猜是哪个人（0052 的 cast 规矩）。
- 小卡：「记住了：…」+【撤回】。撤回 = 软删 memo 笔 / 长回关系记忆旧值。

## 三、「记一笔」按钮退场

线卡和人卡的 jot 那一行（按钮 + 悬停说明 + 人卡那个「也算在哪条线上」下拉）
整个删掉。一个输入框，两种落法，由脑子开没开决定：

| 脑子 | 输入框上写的 | 回车 |
|---|---|---|
| 醒着 | 「一起想点什么……」（不变） | 聊天，Fairwind 顺便判该记什么 |
| 没开 | 「脑子没开：这句会直接记成一笔，不是聊天」 | 直接记成 kind='note' 的笔（走浏览器直连），脑子醒了由盲格子判 |

脑子开没开，App 已经每轮问 `/health`（`checkBrain`），传一个 `brainUp` 进两张卡。
手机上脑子永远没开，那儿就永远是记笔模式 —— 正好。

人卡那颗「刚聊过」打卡按钮不动（它是打卡，不是记笔）。

## 四、双判去掉

`handleChat` 里那段「见面复盘」整个删：DEBRIEF 状态下你说的话，跟别的状态一样交给
同一次回复判，见成了就报 `met`。judge.js 里 DEBRIEF × YOUR_ANSWER 那格和 `parseMet`
成了死代码 —— 这次不删（另一个会话正在改 judge.js，别撞车），下次收拾。

## 五、写口

- `pa_apply_state_move` 加 `p_text`（原话）；`met` 落 meet 笔。旧签名 drop 掉再建。
- `pa_apply_memo(p_kind, p_subject, p_to, p_text, p_src_msg) returns uuid`（service_role）
- `pa_undo_memo(p_src_msg) returns uuid`（anon）
- `pa_rewind_chat` 连带撤 memo（线的软删；人的长回旧值）。

## 六、不变的东西

转移表一格不改。盲格子照旧判脑子没开时记的笔。[[LETTER]] / [[FORM]] / [[FACTS]] 不动。
白名单不动。

## 七、验收

1. 线在 DEBRIEF，你说「见了，聊得不错，他要跟上司商量」→ 一条 meet 笔（原话）+ 小卡
   「见成了」，DEBRIEF 关掉，OWE_MEETING_NOTE 长出来；**盲格子没有再判这条笔**
   （message_tags 里它只有一条 `聊天里定的：met`）。
2. 跟人聊时说「他其实是我 CalArts 的老师」→ 关系记忆末尾多这一句 + 小卡「记住了」；
   撤回 → 关系记忆逐字长回。
3. 跟线聊时说「这个资助只报销机票」→ 线上一条 memo 笔；`v_pa_state` 一字不变
   （尤其「该你回」没被关）。
4. 脑子没开，输入框写着「会直接记成一笔」，回车 → note 笔进时间线；脑子醒了盲格子判它。
5. 「记一笔」按钮在线卡和人卡上都没了；build 不带 jot-howto。
6. 全套测试绿。

## 八、名词表

| 名字 | 是什么 |
|---|---|
| 事件 / 记忆 | 动不动状态机的两种笔 |
| memo | 新的笔的种类，只记不判 |
| [[MEMO]] | Fairwind 报「这句值得记住」的信封 |
| met | [[STATE]] 的新拨法：见成了 |
| 盲格子 | 转移表里按「状态 × 事件」问一个问题的判断，只看这一笔和近几条往来 |
| brainUp | 页面知道的「脑子开没开」 |
