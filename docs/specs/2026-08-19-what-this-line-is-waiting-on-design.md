## 一、为什么推倒

现在的五种由头是**按事实的形状**分的（他回你了 / 该碰了 / 到日子了 / 没回谢 /
见面 48 小时），不是按**你要做什么**分的。三个具体的病：

### 一、「做完了」的证据在往来里，没人去读

CultureHub 那张卡，现在并排摆着两条：

| 卡上写着 | 而事实是 |
|---|---|
| 截止 **8/11**（marketing 素材） | 你 8/12 那封信第一句：「Marketing materials were **submitted the day before yesterday**」—— 8/10 就交了 |
| 该碰日 **9/1** · 出处「connect you with Joo in early Sept」 | 这条是对的，还没到 |

一条已经作废、一条还活着，**而系统分不出来**。作废的证据就在你自己写的那句话里，
它读得到，只是没有任何机制拿它去关掉那个等待。

### 二、五种由头其实是同一件事的五种形状

「8/10 发出去，8 天没回音」说的是**在等对方回信**；
「她说月底联系你 → 9/28 到了」说的是**在等一个日子**；
那 31 条看不见的待办说的是**在等你动手**。

分成五种算，就得写五套「什么时候消失」的规则 —— 而那正是错得最多的地方。

### 三、等多久是写死的

`[7, 21]` 天。投递一份申请和问一句几点开会，等的时间本来就不该一样。

## 二、一条线上只有一个状态

```
        新事实来了，重算
     ┌──────────────────────┐
     ▼                      │
  等待中（有个到点日）──到点──▶ 该动了 ──▶ 已办 / 作废
```

五种情形是同一个状态机的五种**等待类型**，差别只在四个格子：

| 等什么 | 等谁 | 等多久 | 到点做什么 | 提醒在哪 |
|---|---|---|---|---|
| **对方回信** | 对方 | 起草时定，默认 5 / 14 天 | 起草跟进信 | 通知栏 |
| **你回信** | 你 | 立刻 | 起草回信（信息不全先问你） | 通知栏 |
| **一次见面** | 那个日子 | 到那天 | 早上提醒 → 结束后问「怎么样」 | 通知栏 |
| **回谢介绍人** | 你 | 立刻 | 起草致谢 | **人际管理页** |
| **见面 48 小时信** | 你 | 48 小时 | 起草 follow-up | **人际管理页** |

**一条线（或一个人）同时只有一个当前状态。** 这让「合并」有了落脚点 ——
不需要额外的合并规则，状态本身就是唯一的。

## 三、存什么、算什么

> **存的每一条，必须锚在一个不会变的事实上**：一封信、一次见面、一条你记的笔。
> **线的状态不存** —— 每次从「那些标签 + 之后发生的事」现算。

这条规矩是从这一路修过的分叉里总结出来的。分叉的东西有个共同点：
存的是**关于全局的结论**（「下一步该做什么」「上次碰是哪天」），而全局一直在变。

而 `letter_verdicts` 从来没分叉过 —— 它锚在一封信上，
**信的内容永远不变，所以判一次永远算数**。

### 存的（都是标签，锚在一封信 / 一次见面 / 一条笔上）

| 标签 | 锚在 | 什么时候打 |
|---|---|---|
| 这封信要不要回 | 那封信 | 收信之后 |
| 这封信在等对方回什么 | 那封信（我发的） | 收信之后 |
| 合理该等多久 | 那封信（我发的） | 起草那封信时 |
| 这封信约了什么日子（见面 / 再联系） | 那封信 | 收信之后 |
| **这封信 / 这条笔，把之前那个等待解决了吗** | 那封信 / 那条笔 | 收信之后 |
| 起草的正文 | 那个等待 | 到点时 |
| 你按过的记号 | 那条提醒的身份 | 你按的时候 |

### 算的

- **这条线现在在等什么** —— 从最新那些标签，加上那之后发生的事
- **到点了没有** —— 拿等待的到点日跟今天比
- **该动的 / 等待 两栏** —— 同一份状态的两个切片，不是两个列表

CultureHub 那个例子跑一遍：你 8/12 那封信被打上标签「**它交付了 marketing 素材**」
→ 算状态时看到这个标签 → 8/11 那个等待关掉。**不需要谁去勾。**

## 四、收信之后走哪几步

### ① 清洗：这是不是一封「有信息的信」

去掉广告、草稿、收据、通知、日历回执。判据两层：

- **信头和标签**（不花钱）：`DRAFT` / 我发的但没 `SENT` / `bulk` / `no-reply` /
  主题以 `Accepted:` `Declined:` `Canceled:` `Invitation:` 开头
- **内容**（模型）：真人写的、但没有实质内容的（纯客套、自动确认）

> 日历回执这一条是新加的。真例：`Accepted: Di Hu's Zoom Meeting` 正文是空的，
> 模型盯着空正文编了个「可能漏附件，得问一句」，于是它变成了「他回你了」。

### ② 归属：这封信是谁的、哪条线的

```
是现有的人 / 现有的机会线吗？
├ 是 ──▶ 收进那张卡：对话、往来、上下文，一个模块都不落
└ 否 ──▶ 该不该建个新联系人？该不该挂到某条机会线？
         ├ 该 ──▶ 建 / 挂，然后同上，一个模块都不落
         └ 都不该 ──▶ 出一条提醒（见下）
```

判据不限于发信人，也包括**信的内容**（模型判）。

归不到任何地方的，通知栏出一条：

> 邮箱收到一封邮件 / 发出一封新邮件，「内容梗概」，无法归到任何线中，可到后台处理。
> 　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　**[ 不再提醒 ]**

**「不再提醒」只关掉这一条提醒，不删信。** 信永远留在账本里 ——
删信这件事这个项目从来不做。

### ③ 打标签

只对**归进了现有机会卡片 / 联系人卡片**的新信打（见第八节的范围）。

## 五、五种等待，逐条

### 1 · 等对方回信（follow up）

**什么时候进入**：你发出去的信里有「等着对方做点什么」——提 proposal、要材料、
要排期、问一句。这封信被打上标签：**在等什么** ＋ **该等多久**。

**没到点**：在通知栏的「等待」栏里折叠着

> 「某某人 / 机构的某某事务」，已经过去 N 天，设定 follow up 时间为 X 月 X 日。

**到点**：挪进「该动的」，**这一刻才起草**

> 「某某人 / 机构的某某事务」，已经过去 N 天，follow up 已经起草　**[ 打开卡片 ]**

同时 Fairwind 在那张卡的对话里把草稿发给你。

**什么取消这个等待** —— 只有**解决了这件事的信**才算：

| | 算不算取消 |
|---|---|
| 对方回信，答了你等的那件事 | **算** |
| 对方回信，但没答（「收到，回头看」） | 不算，等待继续 |
| 自动回复 / 日历回执 | 不算 |
| **你自己又发了一封** | **不算** —— 否则连发三封等于永远等不到点 |
| 你记一笔说办完了 / 按了「已处理」 | **算** |

取消之后，**以最新那封信为起点重新判**要不要再等。

### 2 · 等你回信

**什么时候进入**：对方来信，判为「要回」。

**立刻进「该动的」**：

> 「某某人 / 机构」发来邮件，「主要内容」需要回复　**[ 打开卡片 ]**

**起草**：先看 Fairwind 手上的信息够不够。

- 够 → 直接起草，在卡的对话里发给你
- 不够 → **先在卡里问你**，你答了再起草

**什么取消**：你回了信（下次收信自然看得见），或者你在别处处理了 ——
后者靠**记一笔**或**「已处理」**按钮，见第七节。

### 3 · 等一次见面

**什么时候进入**：往来里约了时间（真例：Biayna 那封「9/11，12pm，我发链接」）。
这个日子作为标签打在那封信上。

**没到那天**：在「等待」栏折叠着，跟 follow up 放在一起。

**当天早上**进「该动的」：

> 「某某人 / 机构的某某事务」，记得今天见面　**[ 打开卡片 ]**

**见面时间过了**，改口：

> 「某某人 / 机构的某某事务」，今天见面怎么样？　**[ 打开卡片 ]**

同时在卡里问你：见成了吗？聊了什么。你答的那句话**就是一条笔**——
它同时喂给下面两条。

> **这一条需要一个现在没有的数据源。** 查过：手记的见面一共 1 条，
> Biayna 信里那句「9/11 12pm」哪儿都没记。得先能从信里把日子读出来存下来。

### 4 · 回谢介绍人

**什么时候进入**：经人介绍认识的那个人，真回过你了（只发出去没人回，谈不上「聊上了」）。

**显示在人际管理页的「该动的」栏**（不是通知栏）：

> 见到了「某某」介绍的「某某」，跟他说一声谢谢。

草稿发在**介绍人**那张联系人卡片的对话里。

### 5 · 见面 48 小时信

**什么时候进入**：见面成了（你在卡里答了「见成了」，或你记了一笔）。

**显示在人际管理页的「该动的」栏**：

> 和「某某」meeting 了，回复一下。

草稿发在**那个人**的联系人卡片里。**但如果见了多个人、或者那次见面明确是
某条机会线的对公会面 → 草稿发在那条机会线的卡片里。**

## 六、两栏怎么分

> **机会线的事进通知栏，人的事进人际管理页的「该动的」栏。**

判据是**这件事挂在哪张卡上**，不是它长什么样：只存在于联系人卡片、
放不进任何机会线的事，**即便看起来是「需要回信」，也进人际管理页**。

> 这一条撤回了 8/19 早些时候的一刀（当时把人际管理页那块「该动的」删了，
> 理由是「同一件事两个位置」）。**这次不同**：两栏装的是不同的事，
> 不是同一件事的两个位置。合并规则（见下）保证一件事只出现一次。

### 每一栏里两个区

```
该动的  （3）      ← 到点了的
等待    （12）     ← 还没到点的，折叠，露着数字
```

「等待」栏里是 follow-up 倒计时和还没到的见面。**数字一直露在外面** ——
收起来可以，看不见不行。

### 🔔 上那个数字

**数全部**（该动的 ＋ 等待 ＋ 老账 ＋ 判为不用回），不只数「该动的」。
一个把 89 条藏在后面的数字，跟这一整刀要治的病是同一种。

## 七、什么关掉一个等待

四条路，**都留痕迹**：

| 怎么关的 | 怎么发生 |
|---|---|
| **往来里说了** | 一封信 / 一条笔被打上标签「它解决了那个等待」。CultureHub 那句「素材前天交了」就是 |
| **发信这个事实本身** | 你发出了那封该发的信 |
| **记一笔** | 你手写「今天打电话说了」「表单已提交」 |
| **[ 已处理 ]** | 提醒上那个快捷按钮 —— 按下去就是记一笔，只是省了打字 |

### 机会线卡片要补上「记一笔」

联系人卡片有，机会线卡片**没有**（只有 `jot` 那个卡上便签，不进时间线）。
补一个一样的 —— 线下发生的事、打过的电话、提交过的表单，都得有地方记，
否则系统永远只知道邮件里发生的事。

---

## 八、起草什么时候发生、范围多大

**到点那一刻才起草**，不是判断出来就起草。等 5 天的那封，第 5 天才动笔 ——
中间对方回了，那笔钱就省了。

范围：

| | 自动起草 |
|---|---|
| **现有机会卡片**归进了新信 | **是** |
| **人**那边（回谢、见面信） | 只对 **Fairwind 开始之后**建的线（2026-08-03 起） |
| 归不到任何地方的信 | 否 —— 只出一条提醒 |

## 九、卡面上那行金色字

**「这条线现在卡在什么上」显示在卡的封面上**，跟截止时间一样是金色的。

它就是第二节那个状态的一句话：

```
CultureHub Resident Artist · 2026–27
★★★
等 Mattie 九月初把 Joo 介绍给你 · 9/1        ← 金色
```

它跟球权那两个按钮**并排，不互相覆盖**：球权是你随手记的便签，
系统不读它；这行金色字是系统算出来的。**两个不一致，就让你看见不一致。**

## 十、老邮件怎么办

归属已经做完了（人和线都归好了）。要补的是**标签和状态**，范围：

- **2026-08-03 之后**（第一张机会卡建立那天）的往来：照第四、五节全判一遍
- **更早的**：只归属、不补计时。像原先人际管理页那样在下面收着，等你有空捞

理由：2024 年发出去没人回的，补一条「已经过去 700 天，follow up 已起草」没意义，
而且会一次性起草几十封信。

---

## 十一、这一刀不做的

- **不动球权。** 还是你点的，系统不读它 —— 只喂顶栏那个「待处理」筛选。
- **不动红点、新来信、过卡队列。**
- **不做动作对象聚合。** 「回谢 Weidi」挂在 Biayna 身上、「48 小时信」挂在
  Weidi 身上，暂时还是两条 —— 那是下一场。
- **不做应用外的通知**（邮件摘要 / 推送）。

---

## 十二、验收

1. **CultureHub 那张卡**：8/11 那个截止不再显示为待办 ——
   因为你 8/12 的信里说了「素材前天交了」。9/1 那条还在。
2. 你发出一封要材料的信 → 「等待」栏出现一条，写着设定的 follow up 日子
3. 对方回了信但没答那件事 → **等待不取消**，日子不变
4. 你自己又发了一封 → **等待不取消**（否则连发三封永远等不到点）
5. 对方回信答了 → 等待关掉，以最新那封为起点重判
6. 到点那天 → 挪进「该动的」，**这时候才有草稿**，卡的对话里能看到
7. 一封需要回、而 Fairwind 信息不全的信 → 它先在卡里问你，答了才起草
8. 在机会线卡片上「记一笔」写「今天打电话说定了」→ 相关的等待关掉
9. 提醒上按「已处理」→ 等于记了一笔，那条消失，**痕迹留在时间线上**
10. 回谢介绍人 / 见面 48 小时信 **出现在人际管理页**，不在通知栏
11. 同一个人身上的两件事 **只出现一次**，在后发生的那张卡上
12. 🔔 的数字 = 四层加起来，不是只数「该动的」
13. 卡封面上有一行金色的「在等什么」，跟球权并排
14. 2026-08-03 之前的往来不补 follow-up 计时
