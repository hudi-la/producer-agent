# 把 prompt 切成三档：不变的进 systemPrompt，对话留在 message

2026-08-15

## 现在是什么样

每次在一张卡里说一句话，`think()` 收到的是**一根字符串**——`buildPrompt()` 把所有东西拼在一起，
作为**唯一一条 user message** 发出去。拿库里最长那条线（UCSB）量的真实数字：

| 段 | 字符 | 每次说话变不变 |
|---|---|---|
| `## 关于这位艺术家`（profile JSON） | 946 | 不变 |
| `## Ta 的作品与履历（战绩信息库）` | 20,952 | 不变 |
| `## 这条机会线`（卡上字段） | 4,527 | 几乎不变 |
| `## 你们之前的往来` | 39,262 | 只在末尾追加 |
| `## Ta 刚说` + 收尾句 | 47 | **每次都变** |
| **合计** | **65,734** | |

而 `systemPrompt` 里只有 457 字符（人格）。比例 457 : 65,734，大约 1:144。

## 为什么这是个问题

提示词缓存是**前缀匹配**：从第一个字起逐字相同才能接着用，中间断一个字，后面全部全价重读。
服务器只在几个指定位置存状态（断点）。Claude Code 的断点在三处：

```
① systemPrompt 末尾 ── 457 字符      ✅ 稳定，能命中
② 工具定义末尾 ─────── WebSearch/WebFetch schema  ✅ 稳定
③ 消息数组末尾 ─────── 65,734 字符   ❌ 末尾是「Ta 刚说」，每次都变
```

问题全在 ③：断点只能落在这条消息的末尾，而末尾每次都不一样 → 断点作废 →
它前面 65,687 字符（含 20,952 的信息库）**每次全价重读**。

**能省的东西全放在了省不了的地方。**

除了钱，还有三件事：

1. **缓存作用域不是同一档。** SDK 类型文档原话：分界标记之前的块拿 *global cache scope*，
   之后的不拿。systemPrompt 里的块跨会话、跨进程重启都可能命中；message 里的最好也只是
   本会话内命中（联网那十几次往返之间），你说下一句就从零开始。
2. **systemPrompt 是不可伪造的通道。** Fairwind 读外面来的东西：邮件摘要进 `pursuit_messages.content`
   然后进「往来」，WebFetch 抓的网页正文进 tool_result。现在**指令和数据拌在同一根字符串里**
   （contact 分支那段「别写纯问候」、末尾那句「回应 ta」都在 user message 里），
   对模型来说它们跟一封信的摘要是同一个层级。放进 systemPrompt 的东西，任何邮件、
   任何网页都伪造不出来——跟用 `allowedTools` 锁死工具是同一种做法。
3. **会话变长时被压缩的是消息历史，不是 systemPrompt。** `maxTurns: 20` 配联网，
   一轮深度研究抓几个网页就可能撑到触发压缩，那时被摘要掉的正是信息库和往来。

## 改成什么样

SDK 留了口子：`systemPrompt` 可以传 `string[]`，并且导出了一个显式的静态/动态分界标记
（运行时已验证：`SYSTEM_PROMPT_DYNAMIC_BOUNDARY === "__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__"`）。

按「变不变」和「是指令还是数据」切三档：

| 放哪 | 内容 | 为什么 |
|---|---|---|
| **systemPrompt 静态块** | 人格 457 + `## 关于这位艺术家` 946 + `## 战绩信息库` 20,952 | 永不变、是长期知识、不该被伪造、不该被压缩 |
| `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` | | |
| **systemPrompt 动态块** | `## 这条线上的文件` + `## 这条机会线` / `## 这个人`（含那段写信规矩） | 每条线不同，但一次会话内不变 |
| **user message** | `## 你们之前的往来` + `## Ta 刚说` + 收尾句 | 这是对话，且末尾本来就该变 |

改完，那 21,898 字符的静态块跨会话命中；user message 缩到只剩往来和你刚说的那句。

### 三件**故意不做**的事

- **往来不搬进 systemPrompt。** 它是真对话，搬进去丢了「谁说的」这个结构，
  而且它每句都在长——塞进去会让唯一还稳的那块每轮都变，等于把仅存的缓存也毁掉。
  往来该走的路是 `resume` 接着上次会话，那是下一刀。
- **收尾句「回应 ta。直接说话……」留在 user message 末尾。** 按上面第 2 点它该进 systemPrompt，
  但它紧贴着问题的位置是有用的（指令离问题越近越被照字面执行）。搬它会改回话的样子，
  这一刀只搬位置不改行为。留到加固注入边界那一刀一起做。
- **五处后台活儿（收信 / 认人 / 查 thread / 消化 / 建草稿）一个字不改。**
  它们现在的 prompt 里本来就没有信息库，`think()` 改成认块数组之后，
  它们继续传 profile 走老路子——不能因为改缓存反而给它们塞进 21k 字符。

## 不丢东西的判据

`brain/prompt.test.js` 里那条测试就是这句承诺的机器版本：

> 把新的三块（静态 + 动态 + user message）拼起来，必须**逐段包含**老 `buildPrompt()`
> 产出的每一个段落。

不是比长度，是比内容：老 prompt 按行拆开，每一行都得在新的三块里找得到。
差一行测试就红。pursuit 和 contact 两条路各测一遍——contact 那条有它独有的
「别写纯问候」，最容易在搬家时掉。

## 顺带做的：记账

`think()` 拿到 `result` 消息时只留了 `duration_ms / num_turns`，把 SDK 给的
`usage`、`total_cost_usd` 直接扔了（server.js:504）。所以日志里只有「想了 8 轮 / 42 秒」，
没有一个字说这轮花了多少 token、缓存命中多少——涨得快只能靠猜。

改完打成一行：

```
↳ Fairwind 想完了：8 轮 / 42.1s / 首字 3.2s
↳ token：新读 1,240 / 缓存读 21,780 / 出 890 / $0.0412
```

这是验收这次改动的唯一办法：改之前那行「缓存读」应该接近 0，改之后应该接近静态块的大小。

## 施工顺序

1. 新建 `brain/prompt.js`，把拼 prompt 的纯函数整体搬过去（`entryFacts` / `entriesBlock` /
   `filesBlock` / `systemFor` / `artistOf` / `idOf` / `mailboxOf`）。搬过去它们才测得了——
   `server.js` 顶层就 `server.listen()`，import 一下就把服务起起来了，测不了。
2. `buildPrompt` 拆成 `buildSystem()`（返回块数组）+ `buildUser()`；`buildBriefPrompt` 同样拆。
   **老的 `buildPrompt` 留着不删**，只给测试当基准用——它是「一个字都没丢」的那把尺子。
3. `think()` 第三个参数从 `profile` 改成 `system`：字符串或块数组照用，
   传 profile 对象也认（等于只要人格）。这样五处后台调用一个字不用改。
4. 记账。
5. `BRAIN_BUILD` 两边一起挪（`brain/server.js` 和 `src/lib/backends.js`）——
   这次改动不重启就完全不生效，而界面看不出来，正是那个日期存在的理由。
