# 重说：把发错的那句和它之后的对话撤掉，重新说一遍

2026-08-15

## 病

发错一句话，后面就全歪了。

Fairwind 带着这条线的**全部往来**去想（`brain/prompt.js` 的 `historyBlock`），
所以你说错的那一句会一直躺在 prompt 里，被它一轮一轮读到。你在下一句里说
「不对，我刚说错了，其实是……」也没用 —— 错的那句还在，只是多了一句更正，
它得同时消化两份互相矛盾的话。往来越长这件事越糟。

现在唯一的出路是把整条线的往来当没看见，或者开 SQL。

## 药

点自己说过的任意一句 → 就地改 → 「重说」。

那句和它**之后的对话**从此看不见，Fairwind 也读不到；你改过的那句作为一条
新消息发出去，它带着「干净的」往来重想一遍。

不留分支。ChatGPT 那种「1/2 ‹ ›」的版本切换不做 —— 你要的是把说错的话
抹掉重来，不是收藏两个平行宇宙。

## 三条边界

**一、只撤对话，不撤发生过的事。**

被撤的只有 `role in ('artist','producer') and kind = 'message'` ——
你跟 Fairwind 的一来一回。这几样一律不碰：

| 留着的 | 为什么 |
|---|---|
| 邮件（`kind='email'`，role 是 org / artist） | 那封信真的收到了、真的发出去了。你改口不能让它没发生 |
| 你记的备注 / 决定（`role='note'`） | 是你自己记下的事实，不是 Fairwind 说的话 |
| 讲懂（`kind='brief'`） | 对这个机会的核查结果，跟你说错的那句无关 |
| 草稿（`kind='draft'`） | 右栏产出可能正指着它（`deliverables.source_msg`），撤了那条线索就断了 |

代价是：撤完之后那段时间线上可能留着一封信、一条备注，而它们中间的对话没了。
这是对的 —— 事实留着，说错的话没了。

**二、库里是软删，不是真删。**

加一列 `deleted_at`。打上标之后：

- 读面视图 `v_pa_pursuit_messages` 滤掉 → 界面上没有
- `pa_brain_context` / `pa_brain_person_context` 滤掉 → Fairwind 的 prompt 里没有

这两处**必须一起改**。只改视图的话，你看不见但它还记得 —— 那比不做还坏：
你以为撤干净了，它却仍在按那句错话想事情。

对你来说软删和真删没有任何差别（界面上一模一样），差别只在万一撤错了、
或者哪天想知道当时到底说了什么，开 SQL 还捞得回来。这条线上的规矩是
**信息不消失**，而「重说」这个动作要的是「看不见」，两件事不冲突。

**三、按下「重说」之前，什么都没发生。**

点「改这句」只是把那个气泡变成输入框，库里一个字没动。撤掉是「重说」
那一下的一部分 —— 你改到一半走开、按了取消、关掉页面，对话原样在那儿。

这是照 `EditRow.jsx` 那条规矩来的：改之后要确认，存是你说了算。

## 怎么落地

### 一道迁移 0066

```
alter table producer.pursuit_messages add column deleted_at timestamptz;
```

加一条部分索引（`where deleted_at is null`），读面每次都带这个条件。

视图和两个 brain 上下文函数按 0025 的规矩**整段重写**，各加一句
`and deleted_at is null`。

### 一个 RPC：`pa_rewind_chat(p_msg_id uuid) returns int`

- 锚点必须是**你自己的一句普通对话**（`role='artist' and kind='message'`），
  且还没被撤过。不是就报错 —— 这个函数不该能拿来撤别的东西。
- 范围用 `pursuit_id is not distinct from … and contact_id is not distinct from …`
  锁死在同一条流里。机会线的对话 `contact_id` 是空，人的对话 `pursuit_id` 是空，
  用 `is not distinct from` 一句话把两种都盖住，不用分岔。
- 「从这句起」用行比较 `(created_at, id) >= (锚点)`：同一毫秒落库的两条也有确定的先后，
  不会漏一条也不会多撤一条。
- 返回撤了几条，好让界面说得出「撤掉了 N 条」。
- grant 给 anon —— 这是**你在整理自己的对话**，跟 `pa_set_ball` / `pa_set_stage`
  一样走浏览器直连，不经过 sidecar。脑子开没开不该影响你撤自己说错的话。

### 一个纯函数：`src/lib/rewind.js`

`canRewind(m)` 和 `dropFrom(msgs, id)`。SQL 那条规则在前端要有一份逐字对应的
复刻（乐观更新用），所以它必须是纯函数、必须有测试 —— 两边飘了的话，界面上
消失的和库里撤掉的就不是同一批，而你只能看见界面那一份。

### 两个对话组件

`PursuitFocus.jsx`（机会线）和 `PersonFocus.jsx`（人）各加一处。长相一样：

```
                    ✎ 改这句
        ┌────────────────────────┐
        │ 帮我给 Kirk 写封信…     │   ← 点了之后这里变成 textarea
        └────────────────────────┘
         重说   取消
         重说之后，这句和它后面的 3 条对话就没了
```

- Enter 重说 / Shift+Enter 换行 / Esc 取消（跟输入框同一套手感）
- 正在想的时候不给改 —— 那会撤掉一条它还在写的回复
- 「重说」= 撤 → 本地扔掉 → 走原来那条 `send()` 的路把新的发出去。
  撤成功了但发失败，走原来的错误处理：话在库里就说在库里，不在就还回输入框。
