# 设计稿:艺术家的 Producer Agent

> 状态:brainstorming 产出的设计稿,待评审。日期:2026-08-01。
> 这是一个新项目,是 card-writer 的姊妹产品,与"阅读陪伴"无关。

---

## 一句话定位

**一个艺术家请不起的 producer / BD——用一个不失忆的 agent 补上。**

它只是恰好用邮件当主要触达渠道,但本质不是"email app",而是一个**替艺术家跑外联/商务这摊事的角色**:找机会、讲懂机会、一起挑项目、一起写申请、跟进、维护关系。

---

## 背景与动机

### 谁 / 什么痛

用户是做艺术的,需要大量 cold outreach 来推广自己的作品和项目(open call、策展人、画廊、驻地、grant、媒体、potential collaborator)。这条外联链子**每一环都容易卡住**:

1. 怎么形容自己的项目(对自己作品的理解是网状、模糊的)
2. 找名单(内外部筛选都做不好)
3. 逐个写信(每封要个性化,否则像 spam)
4. 主动 follow up(容易忘、容易散)
5. 别人回了怎么回(跨文化礼节 + 非母语的焦虑)

成熟艺术家有画廊/经纪/producer 替他们跑这摊;**新兴的、国际的、独立的艺术家请不起这个人,只能自己硬扛、扛得很烂。** 这个工具把一个"资源好的人才配拥有的角色",平权给所有艺术家。ICP、痛点、forcing function(不做外联就没有职业生涯)都成立。

### 已有的 v0(关键)

用户**已经在用 Claude 定时任务(scheduled task)充当这个 producer**:定时任务替 ta 找机会;但每个机会进来,ta 得**手动判断跟哪个项目有关、要不要改作品、怎么申请**,然后**手动开一个新 Claude chat 把它接着聊、养大**。

这意味着:最大的风险("Claude 能不能当外联 producer")已经被用户用行动验证为"能"。**缺的从来不是智能,是骨架:持久的记忆、真正的 Gmail 管道、一个能看/能改/能指挥它的界面。**

现有 v0 的三个糙点(= 本产品要补的东西):

- 机会散在一堆**互相失忆的 Claude chat** 里,每条都得重新喂背景
- 没有一个地方能**一眼看到"我手上正在推进哪些机会、各自到哪一步"**
- 每条线的上下文全靠用户在脑子和聊天记录之间**手动搬运**

## 核心模型

### 基本单位:机会线(a pursuit)

产品的基本单位**不是"邮件",也不是"人",而是一条「机会线」**——某个项目 × 某个具体机会,一个**会持续长大的、有记忆的协作台面**。

现在用户用"一个临时 Claude chat"充当它;本产品把它变成**持久的、共享记忆的、知道自己该往哪走的**工作台。所有机会线汇成一块**看板**,一眼可见推进状态。

### 地基(三样)

1. **项目大脑 = 一张作品的网**
   项目不是一叠孤立的卡,而是**彼此有连线的网**("既不一样、又可能有联系")。为什么关键:面对一个机会时,producer 要能在网里判断**哪个项目最合适,或哪几个项目串起来的某个角度最合适**。
   - 每个项目手动建一张卡
   - 卡的养成方式:**B 打底(把已有素材一股脑倒进去)+ A 补漏(agent 访谈式追问)**;结构化表单只作为"可手动改的结果视图",不让用户从空白表单开始
   - 与 card-writer 同源:把网状想法/项目压成可用的线

2. **关系记忆 = 人 / 机构**
   通讯录 + 关系记忆:这个人是谁、上次聊到哪、答应过什么、当初为什么找 ta。人卡是未来"入站分拣"时回信自动挂靠的对象。

3. **不失忆的记忆(贯穿一切,见下)**

### 入口:scout

定时任务(scout)找机会——**用户已经在用**。机会进来后落成一张机会线卡,进看板。第一版可以先手动粘机会,或直接接上现有 scout。

## 四根柱子(设计原则)

这个 producer 帮艺术家卸下的,是四样东西:

| 柱子 | 它替你握住什么 | 解放了什么 |
|---|---|---|
| **① 不失忆** | 内容:谁是谁、聊到哪、项目是什么 | 你不用再搬上下文 |
| **② 有流程** | 方法:追一个机会该走哪几步 | 你不用再记路线图 |
| **③ 懂你的作品网** | 你所有项目之间的关系 | 帮你挑对项目/角度 |
| **④ 一起想** | (不替你决定,也不要你独自扛) | 协作台面,不是自动化按钮 |

### 关于 ④「一起想」——定盘星

这**不是一个自动化流水线**(你按钮、它吐草稿),而是一个**共同思考的台面**。最后那份申请是你俩**讨论出来的残留物**,不是任何一方单独产出的。
→ 这决定了界面长什么样:它是个**对话空间**,不是个表单填写器。

### 关于 ①「不失忆」——死线

现有 Claude chat 之所以糙,病根一个字:**忘**。协作弧上只要中间忘了前面聊过什么,协作就断、就得重搬上下文。
→ **整个产品存在的理由,就是给这场"一起想"配一个不会失忆的记忆。记忆是地基,不是功能。**

### 关于 ②「有流程」

一个好 producer 值钱在**脑子里有 playbook**:不同类型机会(驻地 / open call / grant / 冷启动联系策展人 / 媒体 pitch)各有成熟打法。producer 领着走,用户只在每一步参与讨论,不用知道下一步是什么。
→ **每条机会线是一条"知道自己该往哪走"的线**,producer 供给整条弧的骨架并主动推进。
→ YAGNI:第一版不堆僵硬模板。先带一套**通用追机会打法**,再在协作中慢慢学会用户偏好——**流程是长出来的,不是一开始灌满的。**

---

## 协作弧(每条机会线怎么走)

producer 对每个机会走一条固定的弧,三步都是**协作对话**,不是单方交付:

1. **讲懂** — producer 先替你把机会研究透,用具体信息讲给你听(要什么、什么调性、截止、评审是谁)。这一步是它替你做的功课。
2. **一起挑** — 你俩一起在项目网里挑"哪个项目对味/要不要改作品去适配"。
3. **一起写** — 挑定后,顺畅落成一份真能交的申请/信。

(未来:跟进、回信,进入同一条机会线,自动带全部上下文。)

## 架构

### 智能来自 Claude,不是自己造

拆成两层,只负责下面那层:

- **上层 = 智能(不自己写)**:访谈、把项目压成线、研究收件人、起草跨文化邮件、判断"这封回信属于哪条机会线"——**全是调用 Claude API**。写的是**提示词 + 把对的上下文喂进去**,不是"整理逻辑"。
- **下层 = 骨架(自己写,也已会写)**:数据库(项目网、人卡、机会线)、界面、Gmail 管道、把用户输入攒好交给上层。

与 card-writer **完全同架构**(card-writer 背后大概也在调 LLM)——不是新技能,是走过一遍的路。

### 技术选型(核过,非凭记忆)

- **大脑模型**:默认 `claude-opus-4-8`(最强档),`thinking: adaptive`。跨文化措辞、把网压成线这类"要斟酌"的活儿正是它最擅长。
- **成本**:Opus 4.8 = $5 / 百万输入 token、$25 / 百万输出。一封信起草约几分钱人民币;自用与朋友用完全烧得起。省钱可用起草走 Opus、简单分拣走 Sonnet/Haiku。
- **结构化输出**:用 structured outputs 强制项目卡按定好的 schema 吐 JSON(标题/媒介/概念/关键作品/想触达谁),访谈完能干净落成一张规整的卡。
- **栈**:复用 card-writer 的 Cloudflare Pages + Supabase;单开一个新仓库。

### 记忆模型(死线的实现)

- 项目网、关系记忆、每条机会线的往来历史,全部落到 Supabase,持久、可检索。
- 每次 Claude 调用时,把相关地基(对应项目卡 + 对应人/机构 + 这条机会线的历史)一起塞进上下文 → Claude 带着全部 context 回应。**"省心"= 上下文不用用户搬。**
- 这正是替换掉"手动开的、会失忆的 Claude chat"的核心。

### Gmail 管道(后续里程碑)

- 平台是新的(按机会线/关系重组、producer 协作);**邮件收发只是底层管道**——接上 Gmail,读回信、发出去都在平台内完成,用户不跳出去。
- 全量收信 + 分拣时,**关系视图只是盖在完整邮件之上的一层镜头**;底下永远保留"全部、按时间"的原始视图兜底。**分拣只改变优先级和归属,永远不让任何一封信消失或被真正隐藏**(回应"不然会漏"的顾虑)。
- 出站的"发":第一版**落成 Gmail 草稿、用户亲手发**(校准语气/跨文化分寸阶段保留最后一道人工闸);信得过后再加"一键直发"。

## 里程碑 / 动手顺序

一环一环做,每环各自能用,不贪。

- **里程碑 1 — 机会线 + 项目网 + 不失忆的协作**(治此刻最痛的"chat 失忆散架")
  - 项目卡(倒素材→追问)构成的**项目网**
  - 一块**机会线看板**;机会进来(先手动粘或接现有 scout)→ 落成一条能持续聊、持续长大的机会线
  - 每条机会线走"讲懂→一起挑→一起写"的协作弧,**自动带项目网上下文,不用重开 chat、不用喂背景**
  - 大脑走 Claude API
- **里程碑 2 — 接 Gmail 出站**:草稿一键进 Gmail 草稿箱 / 代发,闭合外发
- **里程碑 3 — 入站 + 分拣**:全量收信,按机会线/关系重排,噪音批量化,原始视图兜底
- **以后**:主动型 scout 增强、社媒等其它出口(共用同一项目网)、关系维护

---

## 明确不做 / 护栏(YAGNI)

- **不重造通用邮箱**:面上永远按外联关系组织,底下只借 Gmail 收发能力。
- **第一锤不做全量分拣器**:从"出站/大脑"端起,而非"入站/分拣"端。
- **第一版流程不灌满模板**:通用打法 + 逐渐学习,不堆僵硬模板库。
- **不做团队协作(C)**:目前只服务单个艺术家(自用 + 同类朋友)。
- **不把它做成自动化按钮**:守住"一起想"的协作气质。
