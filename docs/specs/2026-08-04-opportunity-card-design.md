## 这一刀解决什么

上一刀把看板和顶栏理顺了，但卡**打开之后**没动过。点开一张卡，现在是整页换成一条对话流，读起来吃力，而且卡上该有的东西只有一层（标签），另外两层（投的是哪件作品、你们一起写出来的文档）要么是断的，要么根本不存在。

这一刀分五步走，风险从低到高排。前两步是纯前端，今天就能用；后三步是结构性的，先把边界定死，实现留到后面。

**顺序不能反。** 第五步（内部对话分段）一旦落地，两段对话之间就互相看不见了——凡是没被提到「卡上的事实」里的东西，就真的丢了。所以必须先把卡能装什么（三、四）定完，才能动它。

## 零、球权：撤掉「自动」（已实现，迁移 0021）

### 病根

详情页原来给三个按钮：自动 / 待处理 / 等回复。这是把**「谁来判断」**当成一个你要操作的对象摆出来了。可你要回答的问题从来只有一个：球在谁那边。

### 改成什么

两个标：待处理 / 等回复。Fairwind 自己贴一个，你觉得贴错了直接改掉。

### 手改的标什么时候失效

撤掉「自动」按钮会冒出一个新问题：你手改的标，Fairwind 还认不认。

一直钉住不行——你今天标了「等回复」，明天机构真回信了，卡上还写着等回复。那是一句看着很确定、其实已经过期的话，和 0017 撤掉「从 stage 猜球权」是同一个错误。

**定下的规矩：你的修改只管到下一件真事发生为止。**

| 情况 | 听谁的 |
|---|---|
| 手改之后没有新信号 | 听你的 |
| 手改之后来了新的对外通信 | 听 Fairwind 的 |
| 手改之后跟进日才到期 | 听 Fairwind 的 |
| 跟进日在你手改之前就过了 | 听你的（你改的时候就知道它过期了） |
| 从没手改过 | 听 Fairwind 的 |
| 既没手改也没信号 | 两个标都不亮（0017：宁可不说，也不猜） |

### 实现

- `producer.pursuits.ball_at` —— 你哪一刻改的。老数据（2 张）回填 `updated_at`：偏晚是安全方向，最多多钉一会儿，不会凭空翻标
- 视图新增 `ball_eff` —— 球到底在谁那边，一个答案，前端只读这一列。`ball` / `ball_auto` 留着，出问题时看得出答案是怎么来的
- `pa_set_ball` 改一次标盖一次时间戳；置回 null 连时间戳一起清
- 顺手补了迁移文件里漏的 grant：`pa_set_ball` 只开给 `service_role`，可前端是浏览器直连调它的。线上早被手动补过，文件一直没跟上

### 已知取舍

既没往来也没跟进日的卡（33 张里 30 张），抽屉/详情页里两个标都不亮，看着像坏了。留着不改——「宁可不说，也不猜」在看板上是对的，详情页为了好看就开始猜，是同一个错误换个地方犯。

## 一、排版

### 病根

不是行距参数没调好，是**那块内容压根没走 markdown**。

库里 `notes` 存的是：

```
**是什么地方**：Palos Verdes 的植物园（……）。
**流程（已核实）**：❌ 无公开提案通道；总口 **info@scbgf.org** / 424-452-0920。
**判断**：品类沾边但调性偏轻，优先级中等。
```

三行、带加粗。但详情页写的是 `<p className="pf-notes">{p.notes}</p>` —— 纯文本塞进去。所以星号露在外面，三行被 HTML 压成一坨。`why` 同理。对话气泡走的是 `<Md>`，头部这两块漏了。

### 改三处

1. **`why` / `notes` 改走 `<Md>`**，并加 `remark-breaks`。Fairwind 写的是单换行分行，标准 markdown 会把单换行当空格、把三行粘成一段——`remark-breaks` 让单换行变成换行。这个插件同时影响对话气泡，那是想要的：LLM 输出里的换行本来就该是换行。

2. **段间距 8px → 16px，行高显式定 1.65**。现在同段内行距 22px、跨段 30px，1.37 倍，眼睛读不出差别，所以一屏字看着是均匀的一片。改完跨段 38px，1.7 倍。

3. **`.pf-notes` 12.5px → 13.5px**，跟对话气泡同号。它是正文，不是脚注。

## 二、右侧抽屉

### 为什么

现在点开一张卡，整页被换掉，看板消失。而大部分时候你只是想看一眼这条线怎么样了，看完接着看下一张——整页换掉太重。

### 形状

点卡片 → 从右侧滑出 **680px**，**盖在**看板上。

- **盖住，不挤压**。挤压会让七列重排，看板每次开关卡都跳一次
- 看板留在左边，可以一张接一张点过去，抽屉换内容不叠加
- 正文列约 640px（比现在的 560 宽）
- 抽屉里是现在详情页的全部东西：顶条（球权 / 阶段 / 展开 / 关闭）、标题和事实、待办、对话、输入框
- 「展开」→ 现在这个全页，正文列 560 → 720

### 已知取舍

做完一、二，抽屉和全页装的是同一套东西，只差宽度和「看板还在不在旁边」。**全页现在是个占位。** 留着不拆——三、四、五 就是往里填东西的（档案里那件作品的正文和盒子、你们写的文档、邮件往来单独一栏），现在拆了回头要重建。

## 四、文档（未实现）

你和 Fairwind 一起写出来的东西——提案稿、给机构的信、这条线的备忘——现在库里没有任何地方放。

**不需要新的文件存储系统。** 这些是 markdown 文本，文本就是一个 `text` 列。真正需要对象存储的只有二进制（PDF、高清图），而这套东西已经做过一次选择：[0007](../../supabase/migrations/0007_entries.sql) 里图片存的是 URL，不托管。

要做的：新表 `producer.pursuit_docs`，markdown 正文 + 「你确认过没有」。纯增，不动任何现有表。

## 五、内部对话分段（未实现，风险最高）

### 一把刀不能切两种东西

这条流里现在混着两种性质完全不同的东西：

- `kind='email'` —— **真实的对外通信**。球权就是靠它算的，它是这条线的正式记录
- `kind='message'` —— **你跟 Fairwind 的内部讨论**

**邮件往来必须是一条连续的线**，它是事实记录，分段就断了。能分成多段的只有内部讨论：读懂这个机会 / 查他们开什么课 / 写第一稿 / 改稿。

### 新对话记得什么

| 层 | 新一段对话能看见吗 |
|---|---|
| 卡上的事实（标签、字段、作品、文档） | 能 |
| 全部对外邮件 | 能 |
| 别的内部对话 | **不能** |

「你上次问 Palos Verdes 在哪儿」这种闲聊不带进新一段。

### 这就是顺序不能反的原因

内部聊天一隔离，**没被提到「卡上的事实」里的东西就等于丢了**。所以三、四 必须先落地——它们是「提上去」的着陆点。三、四 没有的时候做五，等于给信息挖坑。

### 迁移形状

`pursuit_messages` 加 `session_id`，现有消息全部归到一条「主线」session，一条不动。
