## 一、这件事 `0030` 设计过，后来没建

`0030` 的原话：

> 对方来了新信 → 收信那段顺手落一条 Fairwind 的告知消息。
> 这不是「靠 Fairwind 记得写」——是收信入库的同一个操作顺手写的，
> **结构上做不到「信到了但没告知」**。
>
> 红点从「有封信」变成「Fairwind 告诉你有封信」——你看到的是一句人话
> （谁回的、要什么），不是一个得自己点开翻的哑点。

查了库：`role='producer'` 的 182 条**全是对话回复，一条告知都没有**。
`0058`（四个信号）那一刀把它换成了算出来的 `new_mail` 列，那条消息就一直没建。

`new_mail` 解决了「卡面上看得见有信」，但没解决 `0030` 真正想要的那件事：
**你翻这条线的时候，信的到来在时间线上应该有位置。** 现在往来是往来、
对话是对话，你跟 Fairwind 聊到一半，中间对方回了一封信，对话里什么都看不出来。

## 二、加什么

对话流里多一种消息：`kind = 'arrival'`，`role = 'producer'`。
**一封信入库，就落一条**，跟信在同一个操作里写——漏不掉。

### 对方来信

```
┌────────────────────────────────────────────┐
│ ✉ Sarah 来信 · 8/17                        │
│ Yes, I received it… I think we should      │
│ plan on 2027                               │
│ 展开原文 ▸                                  │
└────────────────────────────────────────────┘
```

### 你发出的信

```
┌────────────────────────────────────────────┐
│ ✉ 你发出 · 8/16                             │
│ Just wanted to make sure the proposal      │
│ form made it to you                        │
│ 展开原文 ▸                                  │
│ ✓ 卡上那条「8-12 前没回音就向 Sarah 跟进」  │
│   算办完了                                  │
└────────────────────────────────────────────┘
```

最后那一行**不是入库时写的**（那时候还判不了），是重判时补上的，见第四节。

## 三、框里放什么：全是事实，不花钱

| 放什么 | 从哪来 | 花不花钱 |
|---|---|---|
| 谁、哪天、哪个方向 | 信头 | 不花 |
| 那一两句 | **正文头一段**，不是模型摘的 | 不花 |
| 展开原文 | `body_raw` | 不花 |

**摘要不叫模型。** 理由有两条：

一、每封信都摘一次，是按信数花钱（几千封），而这个项目立过的规矩是
**量要锁在对象数上**（几十）。

二、更要紧：**模型摘的那一句会跟原文分叉**，而原文就在下面一个「展开」的距离。
截原文的头一段，最坏是截得不好看，永远不会是假的。

## 四、「这条待办我办完了」谁来判

这一条是判断，所以它**不在入库那一步**——入库只落事实。

它落在**重判**那一步（`0078` 建的执行点）：重判本来就要读这个对象的近期往来，
顺手多答一句「卡上那条待办，这段往来里办完了吗」。判成办完了就：

- 写 `next_action_done_at`
- 在那条 `arrival` 的框里补上那一行

**为什么不在入库时判**：入库时只看得见这一封信，看不见「卡上那条待办是什么」
「后来又发生了什么」。而重判看得见整段近期往来——同一个判断，材料多得多。

## 五、不做的

- **不给每封信叫模型写摘要。** 见第三节。
- **不动 `new_mail` / 红点。** 卡面那两个信号一个字不改；这一刀只往对话流里加东西。
- **不给人那边加。** 人卡上的往来是另一套渲染，等这边落地再说。

## 六、验收

1. 收一封新信 → 那条线的对话里当场多一个框，写着谁、哪天、头一段
2. 「展开原文」点开是那封信的原文，跟往来里看到的一样
3. 你自己发出去的信也落一个框，写着「你发出」
4. **信入库了但框没落**，这种状态做不出来（同一个操作里写）
5. 卡上有未完成的待办、而你发出的那封信正好办了它 → 重判之后框里补上
   「✓ 卡上那条『…』算办完了」，并且卡上那条待办变成已完成
6. 框里那一两句**永远是原文的头一段**，不是模型写的
