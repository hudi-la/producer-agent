# Workshop 版路线总纲

2026-08-24 · 分支 `workshop-edition`

这是把 Fairwind 从「Hu Di 的个人系统」变成「十个艺术家各自在用的系统」的总路线。
细节分两张设计稿：[多租户与隔离](2026-08-24-many-artists-one-database.md)、
[语气是数据](2026-08-24-the-voice-is-data.md)。本文只放全局：架构、决定、顺序、验收。

## 一张图

```
──────── 作者托管(唯一的云,约 $35/月,不随人数涨)────────
        Supabase 一个项目
        ├─ 一个数据库,所有学员共用
        ├─ 登录(Supabase Auth 现成的)
        ├─ 每张表带「属于谁」,行级权限守门
        └─ 作者集中改、集中修、能看结构(不看内容)

──────── 学员本机(每人一份,一条命令起来)────────────
        一个安装包
        ├─ 前端(本地跑,不托管——躲开浏览器拦 localhost 的坑)
        ├─ brain(用学员自己的登录身份连库,本机没有 service_role)
        ├─ Gmail 授权(共用作者建的一个 OAuth 应用,页面上点按钮)
        └─ 模型 API key(学员自己的;分层:便宜档判断/好档写信)

──────── 容器(只当第三节课的教室,不当家)──────────────
        沙盒:测试数据、不连真邮箱、随便炸
        只用于开发**扩展模块**;带出来的是模块和配置,不是改过的核心
```

## 已拍板的决定(2026-08-24,他本人)

1. **一个数据库多租户,安全提前做。** 一人一库被否:$325/月随人数线性涨,
   对着 $300 一次性学费。用户自持被否:学员零工程能力,必须能集中修。
2. **brain 和前端都随客户端装,留在本机。** 搬服务器 = 算力账单随人数涨,
   刚否掉的形状从后门回来。
3. **邮件通过客户端取,授权在页面上,agent 不进邮箱。** 后台活儿改成
   brain 自己取好数据、当文字喂给模型;agent 的工具清单里没有任何邮箱工具。
4. **Fairwind 是产品名;每人给自己的 agent 随便起名。**（voice 表的
   `agent_name` 格子,空 = Fairwind。）
5. **功能只增不减。** 已有信息、已有能力,升级不许拿走。
6. **容器沙盒只用来做扩展模块——只增,不改 Fairwind 核心。**
   学员迟早要经历本地安装,那就让它发生在第一节课作者在场时;
   家从第一天起就是本机,容器只是第三节课能随便炸的教室。
7. **Gmail 存草稿:许可和接口留下,发信相关功能暂缓。**
   他自己的发信链路还在调(「我自己用着都不好用」),调好之前
   workshop 版不动发信;`gmail.compose` 那格权限在 scope 清单里预留。
8. **装机在课前:约装机答疑,不占第一节课。**
9. **语气切割不等上课:** 通路现在切好留着,交互(前端还是接口)之后再定。
10. **一月回访课上就约;配置可否分享在报名表上问。**

## 三层与棘轮(定制模型)

- **一层·数据**:档案、作品、人、机会、盒子。靠用来定制,已通。
- **二层·语气和判据**:agent 名字、人格、写信规矩、填表规矩、判断小人格。
  每人一份数据,空 = 代码默认。
- **三层·能力**:源码。进入有四条路(作者发版本/作者写模块给开关/
  vibecoding/花钱找人),vibecoding 只是其一且不是默认。
- **棘轮**:被证明是共同需求的三层东西,降级成二层。这个向下移动就是产品化。
  一月拿一期数据,决定先降哪几样。
- **永远留在源码、挂「别动」牌子的**:状态机判据表(`brain/judge.js`
  TRANSITIONS,错了静默瘸腿)、工具白名单(`server.js`,护栏本体)。

## 顺序(9/15 前)

```
① 模型分层 + API key 通路          ← 独立,先做(本分支进行中)
   └ ①b Gmail 通路统一 + agent 退出邮箱
     ⚠️ 暂缓:动的是他每天在跑的收发链路,而他正在个人版上调发信。
     等他的发信功能调稳,再在这个分支上做,避免两头改同一片。
② 多租户 + 隔离测试                ← 关键路径,最大
   └ 在一个新的 Supabase dev 项目上做,顺便从零重放全部迁移
     (重号 0111–0114 一并清),不碰他的生产库
③ brain 一键安装                   ← 等 ②(setup 第一步是登录)
④ scout 抽离                       ← 独立;砍谁先砍它(课上可用手改模板顶一次)
─── 9/15 ───
⑤ 语气切割                         ← 通路本分支现在做;交互等他定
```

## 验收(全部机器判)

| 事 | 判据 |
|---|---|
| ① | 判断/邮件活带便宜档参数,聊天/写信带好档;两个档位都没配 = 逐字今天的行为 |
| ①b | agent 工具清单里没有任何发信/邮箱能力(一条测试钉死) |
| ② | 两个测试用户各写全套数据;每张表、每个函数、每个端点断言 A 拿不到 B 的任何一行 |
| ③ | 一台干净机器四步跑通,全程不开任何云控制台 |
| ④ | 换一个测试学员的档案,产出的机会源来自他的规则,不含作者画像 |
| ⑤ | voice 全空 = prompt 逐字等于今天(冻结副本当尺子);填哪格换哪格 |

## 分支与合并

- 本分支 `workshop-edition`,从 `batch-and-queue` 的 997593d 分出,
  worktree 在 `.claude/worktrees/workshop-edition`。
- **他的个人版(主目录 + 生产库)不受影响**:本分支的迁移只写文件、
  只应用到 dev 项目;他继续在个人版上调发信。
- 合并时要做的:一次普通 git merge + **迁移重号清理**(两条线都在长号,
  0115 起几乎必然再撞)。不新建仓库——同仓库合并是一次 merge,
  新仓库合并是器官移植。

## 明确不做

- brain 搬服务器 / 替学员保管 API key(成本形状不对)
- TRANSITIONS、工具白名单做成可编辑
- 容器当长期运行环境
- 每人一份可改源码(分叉,升级推不进)
- 现在做发信相关功能(等他的个人版调稳)
