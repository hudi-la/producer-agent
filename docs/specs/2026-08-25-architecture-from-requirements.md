# 从功能要求重新推导架构,再跟现状对账

2026-08-25 · 他的要求(原话立此为据):**只能参考单人版的功能最终效果,
不能从单人版架构的基础上修改得到多租户;重新考虑所有架构;按此检查
这次对话里的所有任务,确定无误后再继续。**

## 方法

「重新考虑所有架构」不等于扔掉代码重写——重写会丢掉几个月真实使用
长出来的判断(状态机、归信规则、缓存切法),而那些恰恰是「功能效果」
的一部分。正确的执行:

1. 把单人版的**功能效果**列成清单(只看它给用户什么,不看它怎么实现)
2. 从这份清单 + 多租户目标,**从零推导**目标架构,过程中不看现状
3. 拿推导结果跟现状**逐块对账**:
   - 一致 → 保留。保留的理由从此是**推导**,不是继承。
   - 不一致 → 现状是化石,改。
4. 化石清单就是任务清单。

## 二、从零推导的架构(不看现状写下的)

A1 **数据层**:托管 Postgres(要现成的登录、行级权限、HTTP API、托管运维
   → Supabase)。**共表 + 每行租户列 + RLS**;不选每人一库(成本随人数线性,
   已否)、不选每人一套表(表数随人数涨、升级要做 N 遍、动态拼表名)。
A2 **身份**:平台自带 Auth;注册即发 per-user 基础行(profile/voice)。
A3 **键**:一切业务实体用代理键(uuid)做主键。**任何来自外部世界的自然键
   (email、gmail 的 message/thread id)在租户内唯一,绝不全局唯一**——
   两个艺术家可以认识同一个人、收到同一个 id 的信。
A4 **每人一行**的东西(档案、语气、脉搏):(tenant) 唯一约束,没有「全库
   一行」这个概念,自然也没有 singleton 列。
A5 **全局共享的只有配置**(区块→视图名这类),只读。
A6 **API 面**:全部以调用者身份执行(invoker + RLS),隔离只在表的 policy
   上定义一次;没有登录 = 什么都没有。绕过 RLS 的特权身份不出现在用户机器上。
A7 **brain**:用户机器上的边车,以用户身份连库;模型 key 用户自己的,分档;
   agent 工具白名单,无邮箱工具、无发信能力(F5 的「字是我的」是结构保证)。
A8 **前端**:与 brain 同机(躲开浏览器拦 localhost),登录门,未配库走演示。
A9 **判据与语气**:行为判据(状态机)在代码里;语气是数据(F6)。
A10 **安装物**:学员拿到的库结构应当是「出生即多租户」的整合基线,
    不是重放作者的个人史(他的数据修复、他的档案条目都不该在里面)。
A11 **验收**:隔离是机器证明——按目录扫全部表/视图,种对抗数据,零字节泄露。

## 四、按 A1–A11 重扫后剩下的化石(本次修)

**D1 · gmail id 还是全局主键**(违反 A3):`mail_headers` / `mail_label_audit` /
`letter_verdicts` 三张表的主键就是 `gmail_message_id`;`pursuit_messages` 的
孤儿唯一索引(pm_gmail_owner_uniq)也没带租户。之前用「跨信箱撞 id 概率是
天文数字」当理由留下——**那是继承的辩护,不是推导的结论**。推导说:租户内
唯一。改 (owner, gmail_message_id),nulls not distinct(无主行之间保持旧语义,
个人版 service 老路一字不变);`pa_mail_headers_upsert` / `pa_judge_letter`
的 conflict 目标跟改。

**D2 · singleton 列还活着**(违反 A4):profile/voice 上的 `singleton` 列和
`pa_set_profile` / `pa_set_voice` 里的 `where singleton`。多租户里没有
「全库一行」这个概念——列删掉,update 不带 where(invoker + RLS 本身就把
更新限定在「你的那行」)。

**D3 · stage_backup_0015**(违反 A10):单人版 2026-08 某次改造的回滚备份表,
是他个人史的一部分,不是功能。空则删(他的生产库里非空,合并时保留)。

**D4 · 学员安装还骑在 110 支个人史迁移上**(违反 A10):机制上 fresh 重放
已剔除数据修复和他的档案条目,但**产品的安装物应当是一份整合基线 schema**
(从最终状态导出,出生即多租户)。归 ③ 一键安装实现(需要 pg_dump;
基线生成后,迁移史只属于他的库,学员库从基线出发单线前进)。

## 五、结论

现架构与推导一致的部分,保留理由自此为**推导**;三块化石(D1–D3)本次修,
D4 并入 ③。验收照旧:隔离测试(A11)+ 「两个学员同一封信的 id、同一个
策展人」对抗种子 + 从零重放全绿。
